# H5 到 Craft 迁移与质量基线

## 迁移结论

Jonwork 后续只以 Craft 作为用户界面、会话入口、任务与项目容器、文件预览和成果侧栏。H5 页面只保留为历史需求与历史成果的只读对照源，不再继续开发，也不把 H5 的路由、表单页面、数据库、认证或任务队列迁入 Craft。

迁移单位不是“页面”，而是可自动匹配的 Skill：用户在会话中用自然语言描述目标，Craft 根据意图选择 Skill，读取当前会话、项目、附件和 Source，以尽量少打断的渐进方式补齐推进下一步所需的信息，信息足够后立即确认需求简报，生成真实报告或图片文件，校验后在右侧成果栏显示。

## H5 历史基线案例

对照案例：`生产验收0616：家用电热水壶用户痛点与设计机会` 与 `生产验收0616：家用电热水壶竞品差异化机会`。

H5 可保留的优点：

- 用户洞察覆盖用户画像、场景地图、体验地图、痛点、需求、机会和概念方向。
- 竞品洞察覆盖竞争格局、专业分析、用户场景、设计机会和来源。
- 参数表单能表达市场、人群、场景、价格带、品牌和企业约束。

H5 暴露的质量问题：

- 用户洞察在“证据完整度 0/100”时仍显示为已完成，画像、频率、严重度与优先级主要是模型假设。
- 历史成果主要停留在页面状态，不能保证存在可下载、可版本化、可审查的真实交付文件。
- 竞品报告虽列出来源，但部分样本与目标市场不完全匹配，且存在被截断的机会标题（“受”），完成态没有挡住结构缺陷。
- H5 的完成进度只代表步骤执行结束，不代表材料充足、验收标准通过或用户批准。

H5 图片基线（`楔形超级跑车概念 / sketch_render_1.png`）：历史资产已保留 1024×1024 尺寸、生成模式、Prompt、任务/资产 ID 与一层版本谱系，这是 Craft 必须保留的有效能力；但该项目的“输入图片”分类为 0，来源实际指向另一张生成图，且没有主体一致性、保护特征、禁用元素和视觉缺陷的逐项通过证据。因此 Craft 不能只做到“文件存在 + 有 Prompt”，还必须记录输入角色、父版本、质量检查和失败/重试结果。

## Craft 必须超过 H5 的验收门槛

报告质量：

1. H5 的有效章节不得丢失；新增执行摘要、证据状态、关键假设、决策建议、责任人/下一步和验收方法。
2. 每个事实能追溯到当前会话材料或 Source；推断与假设必须显式标注。未知值保持未知，不用行业常识伪装成证据。
3. 章节、表格、编号、引用和交叉关系完整；不允许空标题、截断文本、孤立引用或未定义评分。
4. 生成真实 Markdown/Word/PDF/表格等用户指定文件；草稿、待确认、最终版分开保存，修订递增版本且不覆盖已批准版本。

图片质量：

1. 必须生成真实且可打开的图片文件，检查格式、尺寸和非空内容；提示词或聊天描述不能冒充图片。
2. 主体、视角、比例、构图、CMF、背景和数量符合确认简报；局部编辑需检查保护区与修改区。
3. 图片与报告中的产品定位、造型原则、功能约束和禁止项一致；无法从单视图确认的结构不得伪造为工程事实。
4. 不合格图片不得进入最终成果清单；重试后仍失败时明确标记失败与原因。

闭环门禁：

- `deliverable-brief.md` 已由用户确认。
- 材料状态为完整，或用户明确同意带假设继续。
- `deliverable-manifest.json` 使用 schema v2，记录真实 Skill、文件、版本、状态与逐项校验证据。
- 真实成果文件存在且非空，所有验收项通过，并有用户最终批准时间。
- 只有同时满足以上条件，右侧成果栏才显示最终完成。

## 同题对比执行方式

1. 从 H5 历史记录提取输入条件、章节结构、来源覆盖和已知缺陷，只读使用，不导入 H5 账户数据。
2. 在 Craft 新建一个独立项目和会话，以相同产品、市场、用户、场景、价格带与企业约束运行 Skill。
3. 先生成用户洞察和竞品洞察，经询问与确认后形成设计提案；再选择草图渲染/造型融合生成图片，最后用方案评估与对标诊断检查。
4. 按“完整性、证据、正确性、可执行性、视觉一致性、文件交付、版本与验收”七个维度逐项评分，同时保留失败证据。
5. 若 Craft 任一最终成果低于 H5 的有效覆盖，或出现无文件、无来源、结构截断、图文冲突，保持草稿并继续修订，不得宣称迁移完成。

## 2026-08-28 同题实跑记录

Craft 会话 `水壶用户洞察` 已按上述方式执行同题迁移验收：

- 自动匹配 `jonwork-user-insight`，先检查当前会话、附件和 Source，再提出价格带、核心人群、验收颗粒度 3 个关键问题。
- 用户确认中端 100–300 元、含老人与儿童家庭、定性与量化混合，并明确豁免一手材料缺失。
- 已真实落盘 `deliverable-brief.md`、用户洞察状态 JSON 和下游验收标准；历史智能水杯内容只作为方法模板，没有被写成电热水壶事实。
- 当前模型 `deepseek-v4-pro` 曾在生成主报告时返回 `Payment Required`；充值恢复后，同一会话从已确认 Brief 续跑，没有重新询问已确认参数，并补齐 `01-用户洞察预览.md` 与 schema v2 manifest。
- 用户洞察当前仍为草稿：报告和 6 项自动校验已经落盘，但 `approval.approved` 为 false。其余竞品、提案、图片生成与设计诊断阶段尚未实际生成，不能算整链路通过。

这次实跑已经证明 Craft 在询问、材料角色区分、失败续跑、假设标注和真实文件落盘方面优于 H5；但在其余 13 个 Skill 的真实产物、逐项视觉验收和最终用户批准完成前，不能宣称整条迁移链路通过。
