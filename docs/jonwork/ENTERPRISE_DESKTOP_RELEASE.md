# Jonwork 独立桌面端生产交付

## 当前边界

本轮提供的是生产发布基础加固，不代表 14 个业务模块、商业计量或真实客户安装验收已经完成。
公共发布配置已切换为 `production`，账号、下载与更新统一使用 `https://v2.jonwork.com`；公开分享保持关闭，不附带真实凭据。

## 已实现

- 唯一公共发布配置：`packages/shared/src/desktop-release.json`。主进程、界面、分享与打包使用同一配置；未知字段被拒绝，禁止把密钥写入配置。
- 正式版默认数据目录为用户目录下 `.jonwork`；内部开发保持原目录。`JONWORK_CONFIG_DIR` 优先于兼容的 `CRAFT_CONFIG_DIR`。不会自动扫描、复制或删除客户的旧目录。
- 卸载保留 Electron 应用数据。业务目录、账号加密会话和技能缓存是不同数据域，交付验收必须分别核对。
- 账号服务采用 Bun 内置 SQLite。余额与桌面扣费记录在同一事务提交；相同账号/requestId 只扣一次；退款重复调用不增加余额，服务重启后仍可退款。原 JSON 不覆盖。
- 令牌注销记录以哈希持久化，HTTP、新 WebSocket 握手及已建立的账号连接均检查撤销。账号停用、密码重置和角色变更使旧会话版本失效；细节和后台任务边界见下文。
- 桌面账号 IPC 限制为本应用主页面，拒绝子 frame/画布调用；请求拒绝跳转、15 秒超时、最多 16 MiB 响应；会话文件原子替换。
- 生产打包要求签名配置；macOS 要求公证配置。产物指纹门禁拒绝修改配置后直接打包旧主进程/界面。
- Windows 打包不再批量结束系统中的 Node/Electron 进程，依赖安装使用冻结锁文件。

## 运维需要提供的配置

公共配置固定为 `channel=production`、`accountServerUrl=https://v2.jonwork.com` 和 `allowCustomAccountServer=false`。
本部署不允许客户改用其他账号服务。

更新已启用并固定使用 `https://v2.jonwork.com/desktop/updates/`；仍需部署签名安装包、对应平台 YAML 清单和下载文件。
若启用分享，设置 `sharingEnabled=true` 和自有 `shareServerUrl`；仅改域名不能代替部署兼容分享 API、权限控制和用户上传确认。
服务暂不可用时保持关闭，不回退到 Craft。

签名凭据只通过受控构建环境注入，不提交仓库，不写入日志。Windows 使用 `CSC_LINK`/`WIN_CSC_LINK`/`CSC_NAME`，密码由构建系统保护。
macOS 需代码签名身份及 Apple 公证配置。OAuth confidential-client secret 不得编进桌面包，应改为服务端 OAuth 代理。

```powershell
bun run validate:desktop-release

$env:JONWORK_RELEASE = 'production'

```

也可先 `bun run electron:build`，再调用 electron-builder。生产 beforePack 会校验当前配置与主进程、preload、renderer 的 SHA-256 指纹。
指纹用于防止误打旧产物，不代替数字签名或软件供应链证明。受控 CI 必须从固定提交执行干净构建，不能只复制一个指纹文件。
当前新增 CI 运行 Windows/Linux 单元回归和桌面类型检查，不是签名安装包 E2E。

## 账号数据库迁移、备份与回退

1. 升级前停止旧账号服务，备份配置目录、`webui-accounts.json` 与用户工作区。不能同时运行旧 JSON 写入服务与新服务。
2. 新服务首次事务会将旧 JSON 导入同目录的 `webui-accounts.json.sqlite`；JSON 保持原样。
3. SQLite 文件存在后以其中的事务状态为准。旧 JSON 只是迁移前备份，不是最新账本，不能通过删除 SQLite 直接回滚，否则会丢失新流水和余额变化。
4. 本实现使用 SQLite 单机文件事务和 FULL 同步；不要放在网络共享盘，不支持多主机共享文件。大型部署应迁移到服务端关系数据库与独立账本表。
5. 备份时停止服务后复制 SQLite、JSON 和工作区；若发现 SQLite journal/WAL 侧文件，不要在运行中只复制主文件。恢复必须在隔离环境核对账号数、余额和退款幂等。
6. 新 charge API 要求 requestId。账号服务和桌面客户端需协调升级，不兼容无 requestId 的旧客户端。不要为兼容旧版恢复无幂等扣费。

## 收费上线仍然阻断的事项

当前沿用“每条消息 1 积分”的既有业务规则。持久化改造不等于可信商业计量：

- 本地客户端仍可自行执行模型任务，不能仅依赖 preload 扣费防止绕过。
- 现有退款 API 不具备可信的供应商执行失败证明，不能开放为付费资源的最终结算依据。
- 消息接受后异步失败、长任务取消、断网后的未知状态及后台对账仍需服务端任务生命周期接管。
- WebUI RPC 的既有 debit/credit 路径尚未统一为同一任务账本；ERP `ledger_only` 与本地积分需明确唯一最终账本。

正式收费前必须接入受控模型网关，实现任务预占、供应商任务 ID、幂等执行、完成结算和服务端失败补偿。客户端不能决定可信结算结果。

## 后续加固：画布投递与生产启动门禁

- 生产版不再通过 `deferSetup` 将缺少模型连接/凭据伪装成就绪；启动失败停留在可重试的检查页，不删除用户项目，不退回不明工作区。发送前再次检查配置，阻止已知配置缺失时扣费。这是配置门禁，不是可信服务端计量或模型连通性证明。
- 画布不再自动向客户空白项目写入示例。队列与按项目保存的快照统一写入 `canvas/canvas-store-v2.json`，使用互斥文件锁和原子替换；同一主机的 agent/桌面进程共同遵守该协议。
- 画布工具必须传入读取上下文时获得的 `projectId`，每批上限 100 操作；领取绑定项目、revision 与独立投递令牌。完成确认与输出快照在同一存储提交，完成确认可以幂等重放。
- `pending → running → completed/failed/uncertain` 是投递状态，不是供应商图片生成的业务完成状态。30 秒未确认变成结果未知，不自动重跑生成。仅视口/选择操作允许显式重试；其他操作要求用户检查并人工跳过后新建修正任务。跳过保留历史，不能显示为成功或退款。
- 旧状态文件保留不覆盖；旧队列未记录目标项目/是否执行，导入后保持 `uncertain`，须人工核对。所有客户端和 agent 必须协调升级；旧进程继续写旧文件不会同步至新版存储。
- 自动保存按消息顺序提交，错误显示提示；不再在组件卸载时取消尚未发出的防抖保存。尚未实现多窗口协同编辑冲突合并、从服务端快照自动恢复嵌入画布的本地浏览器存储，必须保持为验收待办。

### 画布存储故障处置

本地文件协议不适用于网络共享盘或多主机写入。进程若在提交中被强制终止，锁文件会保留并阻止后续写入；不会仅按超时时长强行抢锁，以免覆盖仍在执行的事务。

管理员需先完全关闭该工作区的桌面与 agent 进程，备份整个 `canvas` 目录，检查 `canvas-store-v2.json` 可解析、版本为 2，并核对临时文件与历史记录；确认不存在写入者后才能移除该工作区的 `canvas-store.lock`。不得通过删除状态文件或自动回退旧 JSON 来“修复”数据。

存储上限 16 MiB、非终态队列上限 500 项；超过后显式阻止写入，不静默丢弃历史。大规模协作部署仍需数据库化存储与可审计归档。

## 账号生命周期与存量连接加固

### 初始管理员与客户开户

公开注册默认关闭。运维首先在账户服务主机、与服务相同的配置目录及发布 profile 下运行 `bun run account:bootstrap-admin`（源码仓库）。这是服务端运维入口，不在客户桌面运行；当前需要源码部署及 Bun 运行环境，不宣称独立服务发行包已包含该工具。

该工具只接受受保护标准输入中的 JSON，字段为 `username`、`password`，禁止通过命令行参数传入密码；可由企业密钥管理系统注入，不把凭据粘贴进终端历史或聊天。不应把该工具暴露为未认证 HTTP 接口。工具检查数据库尚无账号，在同一事务中创建唯一初始管理员，重复引导失败且不覆盖旧账号。测试和运维内部的 `AccountStore.register` 兼容入口不属于公开开户接口。

已有部署不需要重新引导。新开户/密码重置要求 12–128 字符，既有较短密码仍可用于登录，需运维安排轮换。若确需开放自助注册，显式设置 `CRAFT_WEBUI_ALLOW_REGISTRATION=true`；仍必须先有有效管理员，自助注册只能获得普通用户角色。

首次引导会初始化空白目录的配置与默认资源；配置文件采用排他创建，已有损坏配置不会被空配置覆盖。Web 登录页从无缓存的公开策略接口读取注册开关，默认隐藏注册入口；策略读取失败仍可登录，并提示联系管理员开户/重置。

### 管理接口

以下接口要求已认证且有效的管理员，普通用户被拒绝；没有本轮新增管理 GUI，需接入企业后台或由受控运维客户端调用。不得在 URL 中放置令牌或密码。

| 接口 | 行为 |
| --- | --- |
| `POST /api/admin/users` | 用 `username`、`password` 创建普通客户账号 |
| `PATCH /api/admin/users/:id/status` | `disabled` 布尔值停用/恢复账号，不删除项目 |
| `PATCH /api/admin/users/:id/password` | `password` 重置密码，并使该账号旧会话失效 |
| `PATCH /api/admin/users/:id/role` | `role` 变更角色，并使旧会话失效 |
| `GET /api/admin/audit` | 返回最近至多 100 条开户/停用/恢复/重置/角色事件 |

不能停用或降级最后一名有效管理员。停用账号不能登录或新扣费；恢复账号仍需重新登录，旧令牌不会重新变得有效。退款历史保留，不因停用而删除。

审计记录包含操作类型、执行者 ID、目标 ID 与时间，和账号变更在同一 SQLite 事务提交，不包含密码或令牌。当前不是防篡改/WORM 日志、完整财务审计或 SIEM 集成，仍需生产归档与保留策略。

### 会话撤销与上线顺序

- 每次登录有独立 `jti`，同秒登录不复用同一令牌。Cookie 与 Bearer 注销均持久化撤销；HTTP 鉴权检查账号状态和 `authVersion`。
- 账号 Cookie 认证的 WebSocket 在新请求、发送响应、服务端推送/调用和重连回放前检查有效性；空闲连接在下一次 30 秒心跳检查时关闭。撤销连接的缓存事件被清除，不能通过新登录回放旧会话的缓存。
- 只在握手完成签名校验之后，使用同步的账号状态/到期/撤销检查；该检查不能单独用于新连接认证。跨连接伪造客户端响应也被拒绝。
- 已开始执行的工具、外部模型请求和本地 Electron 后台任务不会因关闭 Socket 自动撤回；此轮只保证后续访问和输出受限。任务取消、供应商补偿与退出后的后台策略仍待服务端任务生命周期接管。
- 服务级 Bearer token 是受控运维凭据，不是客户账号，不受客户会话撤销规则控制，绝不能分发给客户。现有本地执行架构仍不等于多租户执行沙箱。
- 旧令牌无 `ver` 时按版本 0 兼容，账号首次重置/停用/角色变更后失效。上线时须停用旧服务实例并协调升级，不能同时运行不认识撤销/版本字段的旧服务。

### 请求资源限制

认证/管理接口请求体上限 16 KiB，其他 WebUI 请求体上限 2 MiB；Node 适配器和 Web-standard handler 均限制流式输入，15 秒未完成读取会终止。超限返回 413、超时返回 408。请求体限额不代替反向代理的连接数、速率、TLS 和异常流量策略。
