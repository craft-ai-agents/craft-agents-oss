# 画布业务与用户操作闭环

> 当前续做：直接操作已扩展到14模块，并接入版本审查、报告上游读取、PI十款计划及Meshy/GLB链路。以 [业务操作与验收](BUSINESS_WORKFLOW_GUIDE.md) 顶部更新为准。下文为基础链路完成时的历史记录，不能据此覆盖尚未执行的真实供应商与业务质量验收。

本轮目标是补齐图片/文本业务共同的执行与交付基础，不代表14个业务模块已逐项验收。

## 用户操作

1. 打开无限画布并进入项目；先准备参考图/草图与生成配置。
2. 在“Jonwork 画布会话”输入要求。提交前同步当前画布，创建原任务；同一面板内后续要求继续原任务，不重复创建会话。
3. Agent 读取 `get_canvas_context`，使用 `apply_canvas_ops` 提交操作。生成任务显示执行进度，保持当前画布打开。
4. 图片/文本生成实际返回并可读取后，才回传生成成功。缺少配置、空结果、取消、部分失败均不显示业务成功；成功的部分仍留在画布供核对。
5. 原任务的 `data/canvas-result-<revision>/` 收到图片/Markdown、成果预览及校验收据。同一revision只允许相同内容重放；修订创建新的目录，不覆盖原成果。
6. 点击“查看成果”“打开成果文件夹”或“回到原任务继续修改”。后续 `get_canvas_context` 可读取最近10次成果路径。
7. 文件保存失败时保留结果回执，可点“仅重试保存成果”；该操作不重新请求生成服务。此时不要关闭窗口或切换工作区。

## 已实现的约束

- 原任务在后台绑定画布项目；切换活动画布后，该任务读取的仍是原画布上下文，不能投递到其他画布。iframe 只接受父窗口消息，执行前验证目标项目；项目切换/关闭后不会把迟到结果当成新项目成果。
- 心跳延长同一投递，不创建新任务；最长30分钟后需要核对。失联不自动重复生图。
- 成果目录只由后台决定，绑定队列记录中的原会话，并验证会话所属工作区；不接受前端文件路径。
- PNG/JPEG/WebP 检查格式特征、大小；Markdown必须非空。单文件16 MiB、单次20项/32 MiB。该检查不是视觉质量或完整图像解码验收。
- 成果标记为“已生成，待审查”，不自动批准为最终设计方案。
- `bun run canvas:build` 重建并同步内嵌画布；完整桌面构建包含该步骤，避免仅修改源码而仍运行旧内嵌页面。

## 验证与边界

- `bun run test:canvas-business`：可控生成器的10项测试，覆盖任务绑定、等待真实回调、无输出、部分失败、项目切换、输入缺失、文本交付、不可覆盖版本、格式/链接路径及心跳。文件发布和队列使用实际临时目录；不代表真实供应商联调。
- 现有46项生产专项回归通过；server-core/session-tools-core/桌面及内嵌画布类型检查通过。
- 浏览器使用独立本地预览，验证新建画布、打开/最大化会话面板、输入保留与提交按钮状态。未在真实账号下调用图片服务，未声称完成桌面“生成→打开成果”的完整人工E2E。
- 此回写入口当前支持图片与文本；视频/音频仍可在画布直接生成，但未接入原会话成果回写。
- 局部改型掩膜、部件来源映射、PI十图一致性、视觉诊断评分与图片转3D依然需要各模块专门实现和验收。此次不是把这些模块全部标记完成。
- 关闭应用后恢复正在生成的供应商任务、窗口级快照恢复及最终用户审批仍未由本轮实现。存量旧版画布和主进程必须一起升级。
