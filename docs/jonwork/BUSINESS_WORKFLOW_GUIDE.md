# 业务操作与验收

## 14模块操作更新（2026-08-31）

本节为当前操作口径，下方九类入口与验证数量为历史记录。

1. 从技能详情点击“打开…操作台”，或打开无限画布→AI会话→业务操作。目录已包含14模块。
2. 图像业务依次选择图片。三类产品调研允许没有图片，但必须填写材料与来源/证据缺口；当前直接报告接口不自动联网检索，只分析提供的摘录与已批准上游。
3. 填写需求，核对输入顺序与输出数量，勾选“确认本次需求”后提交。更改要求、数量、材料或所选图片会清除确认；服务端也检查确认状态。
4. 保持原画布打开。只有实际成果返回、文件类型/数量校验及保存成功，才出现成果版本。每版位于原任务的 `data/canvas-result-N/`，含顺序编号成果、需求/PI规范Markdown、模块状态JSON、预览和哈希收据；不覆盖旧版。
5. 打开成果并逐项检查，在“审查/修改意见”中批准本版本，或填写修改意见。审查记录追加为 `review-N.json` 并绑定成果摘要。静态模块状态保持生成时快照，当前审批状态以最新审查记录和界面为准；不将会话级历史manifest自动改成最终验收。
6. 已批准报告可进入下一步业务：服务端读取原文件而非只传路径，并校验文件未改动。用户洞察默认衔接竞品洞察，竞品洞察衔接设计提案；可自行切换业务。上游报告超过48000字符须先形成已审查精简版。
7. 要求修改时恢复原模块、原输入、原要求和PI规则/品类计划，需重新确认；原图丢失时需重新上传。失败任务可“恢复原需求并修改”；先核对成功部分并人工处理阻断项，再提交修正任务。

### PI系列化

选2–4张种子图，填写共享PI规则和10行不同品类/用途计划。系统对每款使用同一组种子与共享规则，按计划顺序执行10次单图生成；全部10图成功才交付整套成果，并保存PI规范和图序映射。重复品类、缺规则或少于10项会拦截。尚未自动从种子推导/验收家族规则，用户应先通过智能设计解构形成并确认规则。部分失败保留已生成画布节点，但不会把不足10款标记为完成，也不会自动补跑收费请求。

### 图片转3D

当前接入 Meshy 单图接口，输入为小于6MB的PNG/JPEG；WebP或多视角输入需转换/选择单张后再提交。管理员通过服务端进程环境或部署密钥管理配置 `JONWORK_MESHY_API_KEY`，重启后生效。不要把真实密钥放入画布、聊天、版本库或截图。

实现依据 [Meshy Image-to-3D API](https://docs.meshy.ai/en/api/image-to-3d)：先保存“创建中”记录再发起请求，收到任务编号后落盘，后续仅查询原任务；关闭/重启后如任务编号已记录，可点击“重试安全操作 / 继续获取3D结果”。若创建响应丢失且未获得编号，状态保持未知，必须先核对供应商，不能盲目重建。

下载仅接受HTTPS的 `assets.meshy.ai`，不跟随重定向，不向文件下载地址发送API密钥。GLB限制16MiB，检查GLB2头部/分块、嵌入缓冲区、场景可达网格和位置访问器边界；拒绝外部资源及当前预览不支持的必需压缩扩展。这是结构检查，不是完整Khronos一致性或工程验证。

成果版本栏及原任务成果栏均可打开GLB旋转预览，文件夹内可取得原始模型。模型用途和验收要求用于审查，当前接口不将自然语言要求作为几何改型指令。不可见面由模型推断，不承诺尺寸精度、内部结构或可制造性。

## 当前已接入的直接操作

无限画布右下角「AI 会话」展开后，选择「业务操作」，可以直接执行下列业务。不是只选择 Skill 或发送建议：桌面端保存当前画布、绑定原任务，服务端校验输入并创建生成配置节点、参考连线和生成队列；画布等待实际生成、校验输出数量，然后把成果保存到原任务。

| 操作 | 必需输入（按选择顺序编号） | 输出 |
| --- | --- | --- |
| 草图渲染 | 图1草图；图2可选材质/光影参考 | 1–4张效果图 |
| 整图编辑 | 1张产品效果图 | 1–4张编辑结果 |
| 造型融合 | 图1主体、图2造型参考 | 1–4张融合结果 |
| 自定义融合 | 1–5张图；要求中说明图号与部件对应关系 | 1–4张融合结果 |
| CMF发散 | 1张产品图，说明材质/配色要求 | 1–4张CMF方案 |
| 局部改型 | 1张原图、修改要求、下一步涂抹区域 | 1张掩膜编辑结果 |
| 智能设计解构 | 1–5张产品/参考图、解构目标 | 1份带逐图证据的Markdown报告 |
| 方案评估 | 1–5张方案/补充视角图、评估标准 | 1份问题优先级与验证清单报告 |
| 对标诊断 | 图1自有方案、图2–5对标参考、对标目标 | 1份证据对比与差异化建议报告 |

## 用户操作

1. 打开「无限画布」并进入画布项目，上传输入图片。
2. 依次选中输入图；图片组先展开，避免把一组图片误当一张参考。面板显示图1、图2等名称，用于核对主体和参考顺序。
3. 展开右下角「AI 会话」，选择业务，填写需要改变和必须保留的特征，选择输出数量，然后点击「开始…」。
4. 图像业务使用画布中的图像模型；诊断报告使用文本模型且必须支持读图。未配置或提供商拒绝请求时会明确失败，不把排队成功当作生成成功；不自动重复执行失败生成。模型返回空文本也会失败，不保存“无内容”占位报告。
5. 保持原画布打开。结果另建节点，原图不覆盖；实际成果保存后，点击上方「查看成果」「打开成果文件夹」或「回到原任务继续修改」。
6. 多轮修订可选中已有结果重新执行业务，或切到「自由会话 / 继续修改」。每次新请求形成新成果版本。保存失败时用「仅重试保存成果」，不要重复点击生成。

图号和引用使用显式节点标记传入模型，不仅是提示词中描述“参考图片”。业务生成数量不足或部分失败时，已生成图片保留在画布，整个请求不显示完成。输出为待审查草稿：几何一致性、颜色、局部保护项和审美质量仍须逐项审查，文件成功不等于设计验收通过。

### 局部改型

填写要求后点击「下一步：圈选修改区域」，在弹窗中涂抹要修改的部位，再提交。关闭弹窗不会创建生成任务；提交失败时保留弹窗中的要求和笔迹。掩膜须为与原图等大的透明PNG、不超过约1MB/1600万像素，并同时包含可编辑区与保护区。服务端检查编码/尺寸，实际请求前解码核对透明区域和原图尺寸。

实际掩膜会传给图像编辑接口，保存在节点元数据中供手动重试使用。当前自定义模型插件未提供掩膜参数，Gemini编辑路径也不支持掩膜，均明确报错，不静默降级为整图生成。节点内手动重试只更新画布；要形成原任务的新交付版本，请重新通过业务面板提交。掩膜约束仍需对输出逐项人工核对，不能保证任意模型像素级锁定。

### 视觉诊断报告

图文消息携带所选图片，报告要求区分观察、推断、建议与未知项，并列出可见证据、问题优先级、修改动作和用户确认清单。报告回写为实际Markdown文件。空响应/未生成新报告/数量不足不会确认完成；但接口返回非空文本不等于模型真正读懂图片，视觉能力与报告质量仍需真实样例验收。
