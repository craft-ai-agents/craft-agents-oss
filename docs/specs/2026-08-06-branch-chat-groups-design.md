# Дизайн: группы чатов-веток в сайдбаре

- **Дата:** 2026-08-06
- **Ветка:** `feature/branch-chat-groups` (worktree `~/Projects/_craft_worktrees/branch-chat-groups`)
- **Статус:** реализовано (2026-08-06, HEAD ветки)

## Контекст

Действие «Создать ветку из этого сообщения» (TurnCard → ChatDisplay → `SessionManager.createSession`) создаёт новую сессию и открывает её рядом («new panel»). Сейчас:

- Ветка попадает в сайдбар как обычный чат, выше родителя (сортировка по `lastMessageAt` desc).
- Единственный след родства — префикс имени `Branch of <название>`.
- Родительский id **не персистится**: `SessionManager` сохраняет только `branchFromMessageId` и sdk-fork-поля (`branchFromSdkSessionId/SessionPath/SdkCwd/SdkTurnId`), хотя DTO уже передаёт `branchFromSessionId`.
- `SessionMeta` в renderer не содержит branch-полей, поэтому сайдбар физически не может сгруппировать семью.

## Цель

1. Новая ветка появляется в сайдбаре **непосредственно под родительским чатом**, а не над ним.
2. Родитель и все его ветки объединяются в **сворачиваемую группу чатов** («семью») — во всех режимах группировки сайдбара (дата / статус / непрочитанные / проект).

Решения пользователя (зафиксированы при brainstorm):

- **Плоская семья:** ветки веток попадают в ту же группу под общим корнем, без вложенных групп.
- **Позиция семьи:** по последней активности семьи — `max(lastMessageAt)` по всем членам; семья всплывает при сообщении в любом из её чатов.
- **Во всех режимах группировки**, не только в режиме даты.
- **Без backfill:** ветки, созданные до этой фичи, не группируются (у них нет персистентного `branchFromSessionId`).

## Не-цели

- Изменение поведения открытия ветки (по-прежнему открывается в новой панели рядом).
- Вложенные (рекурсивные) группы.
- Backfill/migration существующих веток.
- Слияние с hierarchy задач (`parentSessionId`, kanban, subtasks) — это отдельная система.

### 3. Пайплайн группировки сайдбара

Новый чистый helper `apps/electron/src/renderer/utils/session-families.ts`:

```ts
export interface SessionFamily {
  rootId: string;
  memberIds: string[]; // root первым, ветки по createdAt asc
  lastActivity: number; // max(lastMessageAt)
}

export function buildSessionFamilies(
  items: SessionMeta[]
): { familyBySessionId: Map<string, SessionFamily>; families: SessionFamily[] }
```

Правила построения:

- `rootId(s)` — подъём по цепочке `branchFromSessionId` до сессии без родителя. Ограничение глубины (например, 32) + защита от циклов (visited set). Проверка на каждый шаг: родитель существует в текущем workspace и сам является веткой или корнем.
- **Orphan-ветка** (родитель удалён/архивирован не вместе с веткой / не найден в `items`) → считается корнем своей семьи-одиночки, UI-группы не создаётся.
- Семья-одиночка (нет веток) не даёт UI-группы — ряд рендерится как обычный чат.
- Порядок внутри семьи: корень первый, ветки по `createdAt` asc, tie-break по `id` (только ветки, данных `createdAt` может не хватить — детерминизм).

`apps/electron/src/renderer/components/app-shell/SessionList.tsx`:

- После существующего бакетинга (date/status/unread/project) применять семейную сборку к рядам **внутри каждого бакета**: семья целиком назначается бакету по `lastActivity` семьи (это гарантирует, что члены семьи не разъезжаются по разным датам при активности в разные дни).
- Позиция семьи внутри бакета — по `lastActivity` desc, как сейчас чаты.
- Новая сессия-ветка (`createdAt` ≈ сейчас, но parent выше по «семейной» логике) оказывается **под** корнем — целевое поведение «новый чат под старым».

### 4. UI группы (сворачивание)

`apps/electron/src/renderer/components/ui/entity-list.tsx`:

- Расширить модель: ряд может помечаться как «голова семьи» (корневой чат семьи из ≥2 членов); за ним следуют indent-ряды веток. Сворачивание семьи = скрытие веток-рядов; корневой чат остаётся видимым (он и есть содержание группы; скрывать его нельзя — иначе теряется доступ к основному чату).
- Отдельный заголовок-разделитель семьи **не** делаем: голова семьи — сам корневой чат, с chevron слева от его ряда и бейджем-счётчиком веток (например, `⊟ 3`). Индент веток ≈ 16–20 px + тонкая вертикальная линия-гайд.
- Повторно используем существующие механики EntityList: collapse-тогглы, контекстное меню Collapse all / Expand all.

Состояние свёрнутости (`apps/electron/src/renderer/utils/session-list-collapse.ts` + `useSessionSearch.ts`):

- Ключ семьи: `family:<rootId>`. Персистится в том же `localStorage KEYS.collapsedSessionGroups` со scope-suffix (workspace/filter/grouping).
- Дефолт: развёрнуто (новая семья видна).
- `CollapseAll`/`ExpandAll` во всех 4 режимах добавляют/убирают и семейные ключи.
- `collapseAllGroups` в SessionList дополнительно собирает ключи семей из текущих items.

### 5. Search-режим

- В режиме поиска (`isSearchMode`) семейная группировка применяется так же к найденным рядам; член семьи, не прошедший фильтр, не скрывает семью — отображаются только совпавшие, но в семейном порядке и с индентом (корень, если совпал, первым; иначе первая совпавшая ветка становится «видимой головой» без chevron).

## Обработка краев

| Случай | Поведение |
|---|---|
| Orphan-ветка (родитель не найден) | Рендерится как обычный чат, без группы |
| Цикл/самоссылка в `branchFromSessionId` | Отсечение по visited set; узел считается корнем |
| Семья из одного чата | Без chevron/бейджа, обычный ряд |
| Архивация корня | Ветки, не в архиве: orphan-правило. Архив и обычный список не смешиваются (архивные скрыты из обычного списка уже сегодня) |
| Сообщение в ветке | `lastActivity` семьи обновляется → семья всплывает; бакет семьи пересчитывается |
| Удалённый корень | Как orphan |
| `createdAt` у веток одинаковый | Tie-break по `id` |

## Тестирование

1. **Unit, `utils/session-families.ts`** (vitest, чистые функции):
   - плоская семья: ветка ветки → одна группа, корнем является верхний предок;
   - сортировка: корень первый, ветки по `createdAt` asc;
   - orphan / цикл / одиночка;
   - `lastActivity` = max по членам.
2. **Renderer, SessionList** (vitest по образцу существующих `__tests__`):
   - новая ветка рендерится под родителем во всех 4 режимах;
   - сворачивание скрывает ветки, корень остаётся; состояние переживает remount (localStorage scope);
   - семья из одного чата без chevron;
   - `CollapseAll/ExpandAll` затрагивает семьи.
3. **Server, SessionManager.createSession:**
   - branch-сессия содержит `branchFromSessionId` в session.jsonl header (round-trip read/write).
4. **Ручной smoke (Electron):** создать чат → ветку → ветку ветки; проверить порядок, сворачивание, непрочитанные, архивацию корня, переоткрытие приложения (персистентность).
