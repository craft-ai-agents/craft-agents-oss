# Memory UX spec

The user surfaces a user actually touches. Read [`02-runtime.md`](./02-runtime.md) for what's happening underneath.

## Core principle

**Inspectable + correctable beats invisible + automatic.** The whole reason we picked file-based markdown over a vector blob is so the user can see and edit memory. Every UI surface optimizes for that — not for hiding the file behind a clever interface.

## Surfaces

| Surface | Where | Purpose |
|---|---|---|
| **Memory tab** | Agent detail page (`/agents/<slug>`) | Per-agent memory, list + edit + delete |
| **User profile dialog** | Top-bar avatar menu OR Concierge chat sidebar | Cross-agent USER.md, list + edit + delete |
| **Token-count badge** | Both surfaces | Same pattern as Workspace Context — amber > 8k, red > 16k tokens |
| **Recent activity hint** | Concierge chat header | Optional — "Last we talked: <topic from latest SESSIONS.md entry>" |
| **Memory tool-call surface** | Inline in chat transcript | When agent calls `save_memory`, show a small chip "📝 saved memory: <name>" with click-to-view |

## Memory tab — agent detail

Add a new tab next to the existing tabs on `AgentInfoPage.tsx`. The tab has three areas:

```
┌─ Memory · ~3.2k tokens ────────────────────────── [+ New entry] ─┐
│  Showing 12 entries. The agent reads these every session.       │
├──────────────────────────────────────────────────────────────────┤
│  [feedback] prefers primary sources              edited 4d ago  │
│    User wants every claim cited; treats secondary aggregators...│
│                                                  [Edit] [Forget]│
│                                                                  │
│  [project] RunnerOS workflows phase 2            edited today   │
│    Workflows Phase 2 (outputSchema, retries...                  │
│                                                  [Edit] [Forget]│
│                                                                  │
│  [reference] pipeline bugs in Linear INGEST      created 2w ago │
│    Pipeline bugs are tracked in Linear project...               │
│                                                  [Edit] [Forget]│
└──────────────────────────────────────────────────────────────────┘
```

Behavior:
- Sort: most recently `updated` (or `created` if never updated) first.
- Filter chip row at top: All / User / Feedback / Project / Reference. Click a type chip to filter.
- "+ New entry" opens an edit modal (same modal used by Edit; pre-populated empty).
- Empty state: "Nothing yet. Memory is written by the agent during chat — when it learns something durable, it'll save here. You can also add entries manually."
- "Show expired" toggle in the header — by default, entries past their `expires` date are hidden.

## Edit modal

Same component used for both Edit and New. Mirror `WorkspaceContextEditDialog`.

Fields:
| Field | UI |
|---|---|
| `name` | Text input. Auto-slug from typed text on first keystroke (like agent edit). Disabled when editing existing (it's the identifier). |
| `type` | Radio chips: User / Feedback / Project / Reference. |
| `content` | Multi-line textarea, ~6 rows. Markdown allowed. |
| `expires` | Date picker. Optional. With a "Clear" button. |
| `created` | Read-only; auto-set on save. |
| `updated` | Read-only; auto-set on update. |

Save button triggers the corresponding RPC. Cancel discards.

## User profile dialog

Cross-agent memory lives separately because it broadcasts to every agent. Two access points:

1. **Top-bar avatar menu** — adds a "Memory & Profile" item. Opens the dialog.
2. **Concierge chat sidebar** — small "What I know about you" link in the right pane (when the right pane shows session info). Same dialog.

The dialog is identical to the Memory tab in shape — list + token badge + edit modal — but operates on `USER.md` and uses `scope: 'user'` for the tools. It also makes clear in the header copy: "These memories are shared with every agent."

## Token-count badge

Same component used by Workspace Context (`apps/electron/src/renderer/pages/WorkspaceContextPage.tsx` `TokenBadge`). Three tones:

| Tokens | Tone |
|---|---|
| 0-8k | Neutral |
| 8-16k | Amber — "Memory's getting large; consider pruning." |
| 16k+ | Red — "Memory will crowd out working context. Time to prune or upgrade to recall mode." |

The badge in the header doubles as the trigger for an upgrade-mode flow when we ship Tier 2.

## Memory tool-call inline chip

When an agent calls `save_memory` mid-conversation, the tool call appears in the transcript like any other. Decorate it specifically:

```
📝  Saved memory: "prefers primary sources" (feedback)
    [View] [Undo]
```

- **View** opens the entry in the edit modal.
- **Undo** triggers `forget_memory` and tombstones the name.

Same treatment for `update_memory` ("Updated memory: <name>") and `forget_memory` ("Forgot memory: <name>"). Lightweight visual signal that memory is being touched, with one-click recourse.

## Recent activity hint (optional, Phase 1.5)

When the user opens Concierge, show a small chip in the chat header:

```
📅  Last session: Yesterday afternoon — discussed memory architecture options
```

Pulled from the most recent entry in `SESSIONS.md` (see [`05-sessions-log.md`](./05-sessions-log.md)). Click → opens the session viewer with that session loaded.

This is the difference between "Concierge is forgetful" and "Concierge knows where we left off."

## What we're NOT building (Phase 1)

- A graph visualization of memory entries.
- Memory diff view ("what's changed in the last week?").
- Per-entry search.
- Bulk import/export of memory beyond `git`.
- An "explain why this memory exists" debug surface.

Add when you observe the actual ask. Most of these are anti-patterns at MVP scale.

## Sidebar placement

Memory does **not** get its own top-level sidebar entry. It lives where it's relevant:
- Per-agent → on the agent's detail page (Memory tab)
- Per-user → top-bar menu

This matches how Workspace Context works (lives under Library, not in chrome). Memory is a property of an agent, not a separate noun.

## Accessibility / keyboard

The Memory tab table is keyboard-navigable: arrow keys move row selection, `e` opens edit, `delete` triggers forget (with confirmation). Same affordances as the Workflows list and Workspace Context list.
