# 紧急调度询价编排

AI 在紧急调度流程里的角色是**一名采购员**:读需求、接单、询价、把报价行写回、更新跟进状态。**零新表、零 schema 改动**——只消费业务库既有的状态机,只写人类采购也写的字段。

## 目标库(架构定案,非过渡态)

**读写目标固定是「紧急调度3.0-AI-staging」(下称"写入库"),不是临时 staging、不会切换到别的库。** `base_token=W6HXbwhkVaRezKsXMWLcfItjnLh`,陈昊楠 user 身份为 owner,无权限限制。表 ID:`紧急调度需求=tblUtHNZqbcFtnBl`、`采购询价表=tblgn4QXFdpYn99C`。飞书读写一律 lark-cli `--as user`,命令细节见 `lark-base` skill。

**业务口径的标准来自另一个库,但那个库不写**:本 skill 的字段契约(行数规则、备注写法、来源判断、含税判断等)全部来自对「紧急调度客户需求项目管理表20251011」(`base_token=EWoFbgsDxaBA8LsLxWrce74tnPc`,真实主库,500+ 行活跃业务数据)3433 行真实数据的挖掘校准——**这个库只读、只参照,不写入、不接自动化**。写入库和参照库是两个独立的 Base,字段结构不完全相同(已逐字段核对过写入库覆盖参照库校准出的全部规则所需字段,17/17 匹配),业务逻辑对齐但数据不互通。

还有第三个库「紧急调度3.0 副本」(`LclTbYAOia6es1sdFbacDCgKnld`)——这是写入库的复制源头,**和本 skill 无关**,不读不写,别混进来。

## 状态机(既有,只消费不发明)

- 需求表:`分配状态`(待分配/已分配/已点击)、`接单状态`(待接单/已接单/已拒绝)、`报价跟进情况`(已跟进/无货)
- **AI 的领地**:`接单状态`、`报价跟进情况`、往询价表加行。**禁区**:`分配状态`(分配是业务/自动化的事)、审批类字段、客户报价——绝不碰。

## 工作流

1. **取需求**:处理指定记录,或扫待办(`分配状态=已分配` 且 `报价跟进情况` 为空)。读出 `客户需求型号`、`品牌`、`数量`、`备注（特殊要求）`。
2. **接单**:把该行 `接单状态` 置 `已接单`。
3. **询价三板斧**(全跑,不挑):
   - 本地库存与历史:`procurement-local-inventory-lookup`
   - 平台全量:`procurement-platform-search`(底层 component-data 一条命令全源并发)
   - 供应商候选:`procurement-supplier-shortlist`
4. **合并**:同平台同型号去重留最全行;跨源不比裸数字(币种不同);型号与需求不完全一致的行,差异逐字符写进该行 `备注`。
5. **写回询价表**(见下方字段契约):每个真正拿到"供应商+价格"的报价来源写一行;**查了但没拿到具体供应商/价格的来源,不要单独占一行**——不为了凑行数展开,也不空白造行。**每写完一行就立刻**(不是全部写完后挑一行意思一下)检查 `larkdepot upsert` 返回:`action=created` 时**尽力**截一张产品页证据图并上传该行(见下方"证据截图");`action=skipped`(已存在)和查无占位行都不截图。N 行报价 = N 次截图尝试,一个不少,失败的单独跳过不影响其他行。
6. **推进状态**:
   - 写入了 ≥1 行有效报价 → 需求行 `报价跟进情况=已跟进`。
   - 三板斧全部正常跑完、零有效报价 → 需求行 `报价跟进情况=无货`,**同时**在询价表写一条占位记录(见下方"查无占位行")——这是真实业务台账的标准动作,不是可选项。
   - 有源是 error(反爬/超时/缺creds)→ 不写"无货"、不写占位行;那是"本次未取到",留空状态并在需求行 `备注（特殊要求）` 追加说明,等复跑。
7. **通知**:向 `业务负责人` 发 IM 摘要(报价行数/最优价/币种/交期)。交互会话中发消息前须经用户确认。

## 写回字段契约(采购询价表)

**业务口径(3433 行真实主库全量统计,不是抽样估计)**:报价行数中位数 1 行、均值 1.75 行、62.5% 的需求只有 1 行、17.7% 能到 ≥3 行。**驱动行数的从不是"查了几个平台",而是"真凑齐了几个供应商+价格都有的可比报价"**——查了但没结果的来源不单独占行;不设人为行数上限,按需求特征动态决定:

- 需求量几十件(打样/评估)→ 1 行通常够,不必强凑多行。
- 需求量三位数以上,或备注出现"量産/试产/批量"→ 主动多方比价,2 行左右是正常动作。
- 需求量近千上万,或 `询价性质=P1`,或型号是紧俏 IC/存储芯片 → 允许自然扩展到 3 行以上。**P1 不代表要更快,代表"值得多凑几个候选"**——实测 P1 响应耗时反而比 P2/P3 更长,不要为了抢速度只查一个来源就交差。
- 客户需求原文明确要求"按数量段分别报价"(评估/试产/量产各报价)时,才按"供应商×数量档位"矩阵展开成多行;没有这个明确要求,不要自行拆数量档位凑行数。

| 字段 | 类型 | 写法 |
|---|---|---|
| 关联需求 | link | `[{"id":"rec..."}]`,必填 |
| 供应商名称 | select | **必须用已有选项**;平台名(Mouser 等)缺选项时,写入库自己拥有 owner 权限,可 `+field-update` 直接加选项 |
| 供应商报价型号 | text | 平台返回的原始型号,不归一 |
| 采购价 | number | 数量档最接近需求数量的单价;查无结果时留空,不编 |
| 币种 | select | USD/JPY/CNY/EUR/HKD/SGD/GBP;写报价源自己的币种 |
| 是否含税 | select | 见下方"含税判断",不是简单币种一刀切 |
| MOQ / SPQ | number | **必须同进同退**:拿到报价就两个都抄,查无就两个都空;不要只填一个,也不要用一个反推另一个——MOQ==SPQ(整包)/MOQ<SPQ(可拆卷)/MOQ>SPQ(多包起订)三种都是真实情况 |
| 交期 | text | 见下方"交期写法" |
| 来源 | select | 见下方"来源判断",**不是"拿不准就写无"的兜底** |
| 在库数量 | number | 平台/库存返回的库存数,写这里不写备注;查无留空 |
| 报价单位 | select | 元器件默认 `pcs  `(选项自带尾随空格,先 `+field-search-options` 拿原文);电线电缆类用"英尺"/"m ";化工耗材(硅脂/导热膏)按供应商单位用"公斤"/"克" |
| 额外采购成本+（运费/关税等） | number | 与"预计重量"同批判断:拿到报价就都填(**0 是合法值**,代表国内现货/包邮确实无额外费用,不等于查无留空);查无结果两个都留空。跨境采购(主报价 USD/JPY 等外币)涉及国际运费/关税时,这项费用大概率该用 **CNY** 填(国内结算),不必跟着报价币种走 |
| 预计重量（kg) | number | 见上,与额外成本同批 |
| 链接 | text | 产品页证据 URL;查无留空 |
| 备注 | text | 见下方"备注写法" |

写 select 前先 `+field-search-options` 确认选项存在(询价性质=P1/P2/P3、品牌 272+ 选项——选项池来自真实业务,不许自造)。**`备注（特殊要求）` 是从需求表 lookup 回填的只读字段,写入会被判 READONLY 报错——只能写 `备注` 这一个自由文本字段。`备注（日语）` 默认不填。** formula/lookup/按钮字段全部只读,跳过。

### 采集源 → 供应商名称/来源 映射(实测已有,优先用)

**供应商名称**:mouser→`Mouser`、digikey→`Digikey`、avnet→`AVNET`、tti→`TTI`、tme→`TME`、verical→`Verical`、element14/newark→`Newark`、chip1stop→`chip1stop`、corestaff→`Corestaff Online日本`、master→`Masterelectronics`、lcsc/szlcsc→`立创商城`、**ickey→`云汉芯城`**、rs_uk/rs_de/rs_fr→`RS-HK`(真实站点写进备注)。表里没有的源走"最接近选项或`无`+备注写真实平台名"。本地库存命中(larkdepot 历史价)写`无`+备注注明"本地库存"。

**来源**(3433 行真实分布坐实,不是猜的):`component-data` 查的这批官方/聚合平台,几乎全部落在 `一级平台（自有库存）` 这一类——真实统计 Mouser 228 次、Digikey 138 次、Masterelectronics 143 次、立创商城 42 次(远超它在"搜索引擎自有网站"类目下的 23 次)、云汉芯城 28 次。**所以:AI 采集到的平台报价,来源默认一律填 `一级平台（自有库存）`**,不必逐个判断。`IC网`(752 行,496 个不同中文贸易商名,平均每家 1.5 行——典型广播式个体询价市场)、`专做贸易商`、`淘宝，1688` 这几个选项对应人工贸易商圈广播询价渠道,`component-data` 完全不查这个市场,**AI 基本用不上这几个选项**,不要瞎选。本地库存命中不算外部采购渠道,`来源` 留空或写 `无`。真遇到判断不出的极少数情况才兜底写 `无`。

### 含税判断

- CNY 报价:线上 B2B 商城(立创商城/云汉芯城/有货商城等,系统自动开票)→ `含税`;传统贸易商/个体户(深圳市XX电子)→ 默认 `未税`(含票另议是行业惯例)。
- 非 CNY 外币(USD/HKD/EUR/GBP/SGD 等):默认 `未税`(海外供应商不适用国内增值税逻辑)。
- JPY 报价未税/含税混杂,按供应商实际报价单据判断,不能靠币种一刀切。
- `NA` 选项只在"找到供应商但税务信息真的未知"这种极少数场景用;完全查无结果的占位行,`是否含税` 留空,不要为了填满选 `NA`。

### 交期写法

现货类直接写"现货"(海外/香港/日本仓可写"香港现货"/"日本现货");有明确天数照抄供应商原文"N天"/"N个工作日";跨周写"N周";backorder/期货写"期货N-M周";行业标准/认证文档类物料(无物理交期概念)挪用这个字段写交付形式,如"Digital电子文档"。**查无结果时交期必须留空,不写"0"或编造天数。**

### 备注写法

**必须是自然语言复合叙事句**,可以一句话同时提运费门槛+税务口径+货源性质等多个维度(如"运费511.2USD,进口增值税13%")——**禁止**"AI写回|平台:x|库存:y"这类管道分隔的机器格式(全库 3019 条真实样本里查无一例真实存在这种写法)。格式细节:全角中文标点为主(，、);百分比优先"N%",其次口语化"N个点";货币优先"美金/USD",少用符号"$"/"￥";数量单位优先"个",少用"pcs"(除非直接引用供应商英文页面原文)。**没有实质信息就整字段留空,不要写"暂无"/"N/A"/"待定"这类占位套话**——"暂无"只能出现在描述某个具体渠道确实没回复的完整句子里,不能孤立当占位符用。型号差异、价格阶梯摘要、平台名(当供应商选项装不下时)都写进这里。

### 证据截图(图片字段,86.8% 真实报价行都有)

真实业务数据里 `图片` 字段(attachment 类型,不是 `附件` 那个只读 lookup)填充率 86.8%——采购员报价时习惯截一张供应商页面存证,和 `链接` 字段配套。写完一行报价(`created`)后:

```bash
component-data screenshot "<offer_url>" /tmp/<临时文件名>.png   # 复用共享暖浏览器池,不是另起进程
cd /tmp && lark-cli base +record-upload-attachment \
  --base-token W6HXbwhkVaRezKsXMWLcfItjnLh --table-id tblgn4QXFdpYn99C \
  --record-id <larkdepot upsert 返回的 record_id> --field-id 图片 \
  --file ./<临时文件名>.png --as user   # --file 只认相对路径,必须先 cd
```

**尽力而为,不是硬指标**:少数西方分销商官网页面对单次访问也有反爬验证(和批量抓取同一套机制),`screenshot` 命令会返回 `{"ok":false,...}` 或超时——这种情况**跳过这一行的截图,继续处理下一行,不重试、不阻塞、不因为截图失败就不写报价行本身**。`链接` 字段始终是主证据,截图是锦上添花。

### 查无占位行

三板斧全部正常跑完但零有效报价时,**除了把需求行 `报价跟进情况` 置 `无货`,还要在询价表写一条占位记录**:`供应商名称=无`、`来源=无`(或留空)、`采购价`/`币种`/`是否含税`/`MOQ`/`SPQ`/`交期`/`报价单位`/`额外采购成本`/`预计重量` 全部留空,`备注` 写清楚查无原因(如"mouser/digikey/立创商城均查询过,均无库存或已停产")。这是真实业务台账的标准动作——40.8% 的人类"单行"记录其实就是这种查无占位,不是"一次就中"。咨询了多家但都无结果,合并成 1 条占位说明,不要每个查无的来源单独造一行。

## 幂等(重跑不重行)——机制,不是纪律

**报价行唯一合法写入口**(larkdepot ≥0.2.0):

```bash
larkdepot upsert --app W6HXbwhkVaRezKsXMWLcfItjnLh --table tblgn4QXFdpYn99C \
  --key 关联需求,供应商名称,供应商报价型号 \
  --json '{"关联需求":[{"id":"<需求record_id>"}],"供应商名称":"Mouser","供应商报价型号":"...","采购价":..., ...}'
```

- 查重(业务键三元组)焊死在命令里:重复行返回 `skipped`,新行返回 `created` 并回查自验。**禁止绕过它直接 batch-create/upsert 报价行。**
- `关联需求` 用 link 形态 `[{"id":"rec..."}]`;其余字段按上方契约。
- **查无占位行**没有"供应商报价型号"可用(键字段不能为空),`--key` 改用两个字段:`关联需求,供应商名称`(`供应商名称="无"` 是合法非空值,一个需求只写一条占位,天然幂等):
  ```bash
  larkdepot upsert --app W6HXbwhkVaRezKsXMWLcfItjnLh --table tblgn4QXFdpYn99C \
    --key 关联需求,供应商名称 \
    --json '{"关联需求":[{"id":"<需求record_id>"}],"供应商名称":"无","备注":"mouser/digikey/立创商城均查询过,均无库存或已停产"}'
  ```
- 退出码:1=用法错(键字段缺失等,改参数)/ 3=任务失败(飞书侧错,可重跑),重跑安全。
- 状态字段更新(接单/跟进)天然幂等,直接 batch-update。任何失败后重跑整个工作流必须安全。

## Rationalization Table

| Excuse | Reality |
|---|---|
| "平台 error/超时,这个料就是无货。" | error=本次未取到≠无货;只有三板斧全部正常完成且零报价才写"无货"+占位行。 |
| "查了 5 个平台,那就写 5 行报价。" | 报价行数取决于"真凑齐了几个供应商+价格的可比结果",不是查询次数;没结果的来源不占行。 |
| "这个需求量小,也该多查几个平台凑够 3-4 行。" | 需求量几十件的打样级,1 行足够是常态(62.5% 的人类记录就是 1 行),硬凑多行不符合真实业务习惯。 |
| "P1 优先级,得赶紧交差。" | P1 代表"值得多方比价",不是"要更快"——实测 P1 响应耗时反而比 P2/P3 更长,该多花时间凑候选。 |
| "备注写成'AI写回|平台:x'方便机器解析。" | 人类同事看不懂机器管道格式,全库真实数据零这种写法;备注要写自然语言业务话术。 |
| "没有额外信息,备注写'暂无'占位。" | 没有实质信息就留空,"暂无"只用在描述具体渠道确实没回复的完整句子里。 |
| "供应商名称没选项池里的,来源就写无算了。" | component-data 查的平台几乎全部对应"一级平台（自有库存）",不是无脑兜底写无。 |
| "顺手把分配状态也改了。" | 分配是业务/自动化的领地,AI 只接单、只写询价、只推进跟进状态。 |
| "需求表是空的,先造几条需求。" | 造需求=造业务,AI 只消费别人建的需求;调试/验证用的测试行必须在写完立刻清理,不留在表里。 |
| "价格没返回,按市场价填一个。" | 无 price_breaks 就不写价;编价比缺价更糟。 |
| "额外成本没查到具体数,先写 0。" | 0 是"查到了、确实没有额外费用"的合法值;查无结果应留空,不能用 0 冒充查无。 |
| "顺手把'特殊要求'字段也补全。" | `备注（特殊要求）` 是只读 lookup 字段,写入会报错;只能写 `备注`。 |
