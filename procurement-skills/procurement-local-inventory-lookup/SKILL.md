# 本地库存查询

输入一个型号,查飞书 Base 同步到本地的库存缓存(动态 + A/B1/B2/B3/C 级 + 自家,共 7 张表),给采购展示库存线索。**只读,不往任何表写数据。**

不做比价、供应商真假、下单建议、替代料判断。

## 怎么查:一条命令查全部等级

库存已由 `feishu-db` 工具从飞书 bulk-sync 进本地 SQLite(定时刷新)。一条命令跨 7 张表查,**瞬间返回、无飞书限流、已做型号变体匹配**:

    .agents/skills/feishu-db/bin/feishu-db query --part <型号>

返回 JSON:

- `rows[]`:每条命中含 `grade`(动态/自家/A/B1/B2/B3/C)`/ model / brand / stock / price / moq / supplier / batch / type / updated / match`。
- `match`:`exact` = 型号去符号后完全一致;`fuzzy` = 互为前缀的变体命中(尾缀差异),需逐字符复核。
- `synced_at`:缓存同步时间。`note`:缓存快照提示。

型号写法差异(连字符 `-`、空格、`/`、尾缀)由工具内部归一(去符号 + 大写 + 互为前缀模糊匹配),**不必自己造变体词逐表试**。

## 输出

按等级聚合,给采购可用线索:

- **动态库存表**(grade=`动态`):有无出货/求购记录(`type`)、供应商、数量、价格、`updated` 发布时间。动态表时效性强,注明发布日期让采购判断新旧。
- 各级(A/B1/B2/B3/C)有没有货、哪家供应商、`stock` 库存数量、`price` 单价;**自家库存(grade=`自家`)单列,并把单价(囤货成本)标出来**,方便采购对比市场行情。
- **型号逐字符比对**:对 `match=fuzzy` 的每条,把返回的 `model` 和用户原始型号逐字符比较,写清差在哪——"你要的是 `55A0111-24-2`,这条是 `55A0111-24-2L`,多了后缀 L"。不要只写"相近命中需复核"这种模糊话。
- **跨表交叉验证**:同型号只有一张表(一家供应商)报有货、其他等级全无 → 标注"仅此一家报有货,无其他源印证"。多家有货时比较单价,某家明显偏低(低 30%+)就标出。A 级可信度高于 C 级——A 级无货但 C 级有货时把等级差异写清楚。
- **供应商只有 1 家**:全部结果只有 1 家有货时,AGENTS.md 层面会自动补查供应商档案。这里只如实呈现。
- `rows` 为空就如实写"本地无库存记录"。
- 末尾带上 `synced_at`,并提醒"为缓存快照,下单前对中标行可再 live 复核"。

> 只挑库存相关字段(型号/库存/单价/供应商/等级)给采购,别整段 JSON 照搬。

## 查不到 = 没有:空结果是权威答案,别 fallback

本地缓存是飞书 7 张库存表的**完整镜像**(每张整表同步)。所以:

- 命令成功(输出里有 `synced_at`)→ 结果即权威。`rows` 空 = **该型号本地确实无库存**,直接如实写"本地无库存记录(截至 `synced_at`)",**到此为止,不要再查 lark-cli**。查不到不是缓存的毛病,是飞书里本来就没有——live 查同一个源只会得到同样的空,还更慢、撞限流。
- **大多数型号本就不在库存里,空结果是常态,也是有用的答案**(省得采购空等)。不要因为"没查到"就怀疑工具、反复换法子、退回 live。
- 仅当采购**明确要求**对某个型号做最新核实时,才对**那一个型号** live 查一次(下方命令),不要对每个空结果都这么做。

## 只有缓存真的坏了才 fallback

仅当 `feishu-db query` **命令本身失败**(二进制缺失 / 报错 / 输出非 JSON),或 `synced_at` **为空**(从未成功同步过)时,才说明缓存不可用,退回直接查飞书。**串行、一张一张查,绝不并发**;遇限流 `800004135` 等几秒重试,静默处理:

    lark-cli base +record-search --as user --base-token Mjlkb49B9aoptssVw8Jc0wGwnhh --table-id <table-id> --json '{"keyword":"<型号>","search_fields":["型号"]}'

表 id:动态 `tbli1WYTb1Xn2MSa` / 自家 `tblSUjXdehzkxIbK` / A `tblzQbSnVNhGszYA` / B1 `tbldOthm6zmFonDM` / B2 `tblqaoi5UuUGybxF` / B3 `tbld53dBj2dvI1R6` / C `tblBbvvRKB0Ziioz`。子命令必须带 `+` 前缀。若返回 `91403 permission`/登录失效,如实告诉用户需要开 base 读权限 / 重登 lark-cli,不要编造库存,不要反复切身份重试。

## 边界

有库存 ≠ 可下单。型号扩展/合并不等于型号等价。只读,不写 `查找库存` 或任何表。
