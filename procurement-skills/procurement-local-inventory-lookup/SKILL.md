# 本地库存查询

输入一个型号,查飞书 Base 同步到本地的库存缓存(动态 + A/B1/B2/B3/C 级 + 自家,共 7 张表),给采购展示库存线索。**只读,不往任何表写数据。**

不做比价、供应商真假、下单建议、替代料判断。

## 怎么查:SQL 直查全部等级

库存已由 `larkdepot`(原 feishu-db)工具从飞书 bulk-sync 进本地 SQLite(定时刷新)。**先跑一次 `larkdepot schema` 看这 7 张表(动态库存表/自家库存/A级供应商库存/B级供应商库存1/2/3/C级供应商库存)各自的真实列名**——各表字段名不完全一致(型号列可能叫"型号"/"品名"/"料号"等,库存列可能叫"库存数量"/"数量"等),照 `schema` 输出为准,不要凭记忆硬编码。

拿到列名后用 `query sql` 跨表 UNION,`norm()` 做型号变体匹配(去 `-`/空格/`/` + 转大写,**不必自己造变体词逐表试**):

    larkdepot query sql --sql "
      SELECT '动态' AS grade, 型号 AS model, 品牌 AS brand, 库存数量 AS stock, 单价 AS price, 供应商名称 AS supplier, 更新时间 AS updated
      FROM 动态库存表 WHERE norm(型号)=norm('<型号>')
      UNION ALL
      SELECT '自家', 型号, 品牌, 库存数量, 单价, NULL, 更新时间
      FROM 自家库存 WHERE norm(型号)=norm('<型号>')
      -- 其余 A/B1/B2/B3/C 五张表同理拼接,列名以 schema 输出为准
    "

- 每张表用 `norm(<该表的型号列>)=norm('<型号>')` 各自匹配,`UNION ALL` 拼一次查完全部等级。
- 结果为空 = 该型号本地确实无库存(见下方"查不到 = 没有"),不是漏查了某张表。

## 输出

给采购一张库存明细表,按等级聚合;`rows` 为空就如实写"本地无库存记录"。

| 等级 | 型号 | 匹配 | 库存 | 单价 | 供应商 | 更新时间 | 备注 |
|---|---|---|---|---|---|---|---|
| 自家 | 55A0111-24-2 | 完全一致 | 500 | ¥3.20(囤货成本) | - | 2026-06-30 | - |
| A | 55A0111-24-2L | 模糊 | 1200 | ¥3.50 | XX电子 | 2026-06-28 | 差异:多了后缀 L |
| 动态 | 55A0111-24-2 | 完全一致 | - | ¥3.10 | YY贸易 | 2026-06-29 | 求购记录,非现货 |

写法要求:

- **动态库存表**(grade=`动态`)单独一行,`type` 是出货还是求购、`updated` 发布时间写进"备注",时效性强,让采购判断新旧。
- **自家库存**(grade=`自家`)单独一行,"单价"列注明是囤货成本,方便采购对比市场行情。
- **型号逐字符比对**:`match=fuzzy` 的行,"匹配"列写"模糊","备注"列逐字符写清差在哪——"差异:多了后缀 L"。不要只写"相近命中需复核"这种模糊话。
- **跨表交叉验证**:同型号只有一张表(一家供应商)报有货、其他等级全无 → 备注标"仅此一家报有货,无其他源印证"。多家有货时比较单价,某家明显偏低(低 30%+)在备注标出。A 级可信度高于 C 级——A 级无货但 C 级有货时在备注写清楚等级差异。
- 表后带上 envelope 里的 `freshness.synced_at`,并提醒"为缓存快照,下单前对中标行可再实时复核"。

> 只挑库存相关字段(型号/库存/单价/供应商/等级)给采购,别整段 JSON 照搬。

## 查不到 = 没有:空结果是权威答案,不要降级

本地缓存是飞书 7 张库存表的**完整镜像**(每张整表同步)。所以:

- 命令成功(envelope 里 `freshness.synced_at` 非空)→ 结果即权威。`data` 空 = **该型号本地确实无库存**,直接如实写"本地无库存记录(截至 `freshness.synced_at`)",**到此为止,不要再查 lark-cli**。查不到不是缓存的毛病,是飞书里本来就没有——实时查同一个源只会得到同样的空,还更慢、撞限流。
- **大多数型号本就不在库存里,空结果是常态,也是有用的答案**(省得采购空等)。不要因为"没查到"就怀疑工具、反复换法子、降级到实时查询。
- 仅当采购**明确要求**对某个型号做最新核实时,才对**那一个型号** 实时查询一次(下方命令),不要对每个空结果都这么做。

## 只有缓存真的坏了才降级

仅当 `larkdepot query sql` **命令本身失败**(二进制缺失 / 报错 / 输出非 JSON),或 `freshness.synced_at` **为空**(从未成功同步过)时,才说明缓存不可用,降级直接查飞书。**串行、一张一张查,绝不并发**;遇限流 `800004135` 等几秒重试,静默处理:

    lark-cli base +record-search --as user --base-token Mjlkb49B9aoptssVw8Jc0wGwnhh --table-id <table-id> --json '{"keyword":"<型号>","search_fields":["型号"]}'

表 id:动态 `tbli1WYTb1Xn2MSa` / 自家 `tblSUjXdehzkxIbK` / A `tblzQbSnVNhGszYA` / B1 `tbldOthm6zmFonDM` / B2 `tblqaoi5UuUGybxF` / B3 `tbld53dBj2dvI1R6` / C `tblBbvvRKB0Ziioz`。子命令必须带 `+` 前缀。若返回 `91403 permission`/登录失效,如实告诉用户需要开 base 读权限 / 重登 lark-cli,不要编造库存,不要反复切身份重试。

## 边界

有库存 ≠ 可下单。型号扩展/合并不等于型号等价。只读,不写 `查找库存` 或任何表。

## Rationalization Table

| Excuse | Reality |
|---|---|
| “缓存查不到，肯定是工具漏了，我再实时查一遍。” | 命令成功且有 `freshness.synced_at` 时，空结果就是权威答案；不要降级。 |
| “我自己造几个变体逐表查更保险。” | 型号归一和模糊匹配已在工具内完成，重复查会慢且引入冲突。 |
| “模糊命中就算有货。” | `match=fuzzy` 必须逐字符说明差异，不能当作型号完全一致。 |
| “把 JSON 全贴出来最完整。” | 只给采购库存相关字段和必要核对点。 |
