# 供应商候选名单筛选

输入品牌/品类(可带型号特征),查飞书 Base 同步到本地的供应商档案缓存,整理采购可联系的候选名单。**只读,不写表。**

不做供应商真假、付款风险、价格优劣、下单判断。

## 怎么查:SQL 直查

供应商档案已由 `larkdepot`(原 feishu-db)工具从飞书 bulk-sync 进本地 SQLite。**先跑一次 `larkdepot schema` 看供应商档案表的真实列名**(照 schema 输出为准,不要凭记忆硬编码),按品牌/品类跨"主营品牌"/"优势产品"/"询价品牌"三列匹配,**瞬间返回、无飞书限流**:

    larkdepot query sql --sql "
      SELECT 供应商全称,供应商类型,供应商等级,主营品牌,优势产品,联系方式,联系媒介,\"官网|店铺\",供应商状态,备注,总分
      FROM 供应商档案
      WHERE 主营品牌 LIKE '%<品牌或品类>%' OR 优势产品 LIKE '%<品牌或品类>%' OR 询价品牌 LIKE '%<品牌或品类>%'
    " --limit 50

返回 envelope `data[]`:每条含供应商全称 `/` 供应商类型 `/` 供应商等级 `/` 主营品牌 `/` 优势产品 `/` 联系方式 `/` 联系媒介 `/` 官网|店铺 `/` 供应商状态 `/` 备注 `/` 总分。

- **品牌中英文互查**:用户给中文品牌(如"欧姆龙"),也用英文("Omron")再查一次,反之亦然。两次结果合并去重。对照表见 AGENTS.md「品牌中英文对照」。
- **按品类**:品类词(如"继电器""连接器")直接当 `--brand` 传——优势产品字段里也会命中。

## 筛选原则

- 优先:主营/优势品牌命中、原厂/授权代理/授权分销商/平台自营、已建联、联系方式明确。
- **匹配原因看命中强弱**:"主营品牌"命中(强)> "优势产品"提及(中)> 仅历史线索(弱)。结果里"主营品牌"含目标品牌的是强匹配。
- **供应商类型只看 `type` 字段**(如"授权代理/授权分销商""贸易商"),不拿 `note`/付款风险文字推断类型。贸易商可入候选,但必须标明类型,不伪装授权/原厂。
- **联系方式 vs 联系媒介**:有具体 `contact` 才写"联系方式可用";只有 `media`(QQ/微信/电话渠道)时只能写"有联系媒介记录"。
- **短品牌名防部分匹配误命中**(`ST` 不等于 Kingston/Transcend/storage;`TI` 易误中)——核对"主营品牌"是否真含该品牌,不要被"优势产品"/"备注"里的部分匹配带偏。

## 输出

给采购一张候选供应商表:

| 供应商全称 | 类型/等级 | 匹配原因 | 联系方式/媒介 | 官网/店铺 | 供应商状态 | 备注 |
|---|---|---|---|---|---|---|
| XX电子有限公司 | 授权代理/A | 强(主营品牌命中) | 138xxxxxxx | example.com | 合作中 | - |
| YY贸易 | 贸易商 | 弱(仅历史线索) | 微信联系媒介 | - | 未知 | 需确认是否仍合作 |

"匹配原因"列写强弱并注明命中字段(主营品牌/优势产品/历史线索)。表后列:未覆盖项;人工确认项(是否仍合作/可供该型号/有无现货报价/需否补授权)。

> JSON 字段挑上面这些给采购,别整段照搬。

## 查不到 = 没有:空结果是权威答案,不要降级

本地缓存是飞书供应商档案表的**完整镜像**(整表同步)。命令成功(envelope 里 `freshness.synced_at` 非空)时:`data` 空 = **档案里确实没有供该品牌/品类的供应商**,如实写"档案内暂无匹配供应商(截至 `freshness.synced_at`)",**不要再查 lark-cli**。查不到是档案本来就没有,实时查同源只会同样空、更慢、撞限流。不要因为没查到就怀疑工具、降级到实时查询。

## 只有缓存真的坏了才降级

仅当命令**本身失败**(二进制缺失 / 报错 / 输出非 JSON)或 `freshness.synced_at` **为空**(从未同步过)时,才降级直接查飞书(子命令带 `+` 前缀;中英文两次查询串行、不并发):

    lark-cli base +record-search --as user --base-token Mjlkb49B9aoptssVw8Jc0wGwnhh --table-id tblbtuMHFIOr6Oss --json '{"keyword":"<品牌>","search_fields":["主营品牌","优势产品","询价品牌"]}'

`--as user` 下若返回 `91403 permission`/登录失效,如实告诉用户去开 base 读权限 / 重登 lark-cli,不要编造,不要反复切身份重试。

## 边界

候选 ≠ 准入。有候选 ≠ 有库存。付款风险字段只展示,不在本 skill 做风险判断。只读不写。

## Rationalization Table

| Excuse | Reality |
|---|---|
| “档案没查到，我再实时查飞书试试。” | 缓存命令成功且有 `freshness.synced_at` 时，空结果就是档案内暂无匹配。 |
| “note 里像授权，就按授权代理写。” | 供应商类型只看 `type` 字段；备注不能推断授权身份。 |
| “候选供应商很多，说明有货。” | 候选只代表可联系对象，不代表库存、报价或准入。 |
| “短品牌名匹配到了就算命中。” | `ST` / `TI` 等短词要核对主营品牌字段，防止部分匹配误命中。 |
