# 平台报价查找

本 skill 负责采购业务层的平台结果整理。这里按采购需要处理采集层返回的结构化证据。

## 工作流

1. 确认入口：本地库存已经查完为空，或用户明确要求继续查外部平台。
2. 记录库存查找情况：每次输出都固定写本地库存是否已查询、结果是什么；用户直接要求外部平台且未查本地库存时，也要写清“未查询”。
3. 保留用户原始型号：不要先合并后缀、包装、温度等级或版本号。
4. 一条命令跑全部平台：`component-data <型号> --json` = 一轮并发跑当前全部源（官方 API + 直连分销商 + 国内聚合）。全量一轮通常约 1 分钟，慢源拖尾最长约 2 分钟——**不要因为过了一分钟没返回就中断重跑**。**不要手工截取清单、不要挑“核心平台”、不要分轮——直接全量跑。** 采集命令、字段与终态语义见 `component-data` skill。
5. 展示搜索覆盖：先列出本次实际查询的平台覆盖，来自本次 envelope 的 `sources[]` 和每源终态（ok 有行 / ok 无匹配 / error），不能凭印象补。每个源都有终态才能写“平台已覆盖完成”；有源缺状态就写“仍有平台状态未确认”。error 的源列出 + hint，不写成无货。
6. 取得结构化平台证据：只消费返回的型号、平台、品牌、描述、库存、价格、MOQ、交期、链接和错误状态。
7. 做型号一致性核对：平台返回型号与用户型号不完全一致时，逐字符写清差异，例如多了包装后缀、少了温度等级、版本字母不同。
8. 合并同一平台的重复行：同平台同型号保留库存/价格最完整的行，证据链接不同但信息互补时可以合并到同一行。
9. 区分状态：有结果、正常无匹配、本次未取到要分开写；访问受限或报错（error+hint）只能说本次未取到，不能说成无货。替代候选只在任务转为替代料判断时使用，不混入普通平台报价结果。

## 输出

输出给采购看平台证据，不输出采集过程。没有上层指定格式时，用下面的结构：

```text
库存查找情况
- 本地库存：已查询 / 未查询
- 结果：无记录 / 有记录 / 用户直接要求外部平台
- 说明：已查本地库存无记录，继续查外部平台；或用户直接要求查外部平台，本轮未查询本地库存

平台总览表（本次覆盖 N 个源）

| 平台 | 状态 | 返回型号 | 库存 | 最低价/MOQ | 交期 | 证据 | 备注 |
|---|---|---|---|---|---|---|---|
| digikey | 有库存 | LM358DR2G | 34,261 pcs | $0.24 @1 | 未返回 | 产品页 | 完全一致 |
| ickey | 有库存 | LM358A-SR | 16,000 pcs | ¥0.42 @750 | 5-10 工作日 | 来源字段无链接 | 差异：多后缀 A |
| avnet | 有报价/可订 | LM358DR2G | 未返回 | $0.21 @2500 | 未返回 | 搜索页 | MOQ 2500 |
| tme | 无匹配 | - | - | - | - | 搜索页 | 正常无匹配 |
| rs-uk | 本次未取到 | - | - | - | - | 搜索页 | 反爬拦截 |
| newark | 本次未取到 | - | - | - | - | - | 缺 API key |

平台状态汇总：有库存 X / 有报价或可订 X / 已知无库存 X / 无匹配 X / 本次未取到 X。

详细结果（仅展开有库存、有报价或需要人工确认的平台）

digikey
- 返回型号：LM358DR2G；型号一致性：完全一致
- 品牌/描述：onsemi / IC OPAMP GP 2 CIRCUIT 8SOIC
- 库存：34,261 pcs
- 价格/MOQ：$0.24 @1 起
- 交期：未返回
- 证据：https://www.digikey.com/en/products/detail/onsemi/LM358DR2G/661123
- 需确认：无

ickey
- 返回型号：LM358A-SR；型号一致性：差异：你查的是 LM358，返回 LM358A-SR，多了后缀 A
- 品牌/描述：3PEAK/苏州思瑞浦微电子 / SOP-8
- 库存：16,000 pcs
- 价格/MOQ：¥0.42 @750 起
- 交期：5-10 工作日
- 证据：来源字段无链接
- 需确认：后缀 A 是否可接受

未展开平台说明：
- 无匹配：<平台列表>
- 本次未取到：<平台：原因>
```

写法要求：

- **先库存情况，再表格后明细**：每次输出必须先写 `库存查找情况`；进入外部平台结果后，第一屏必须先显示 `平台总览表`；不要先写型号科普、推荐顺序或长篇说明。
- `库存查找情况` 固定保留三项：`本地库存`、`结果`、`说明`。不知道本地库存是否查过时写“未查询/未提供”，不要省略这一段。
- 每个源必须一行。表格源数必须等于本次 `component-data` envelope 覆盖的源数（见 `sources[]` / `sources_total`）；缺源就写“仍有平台状态未确认”。
- 表格状态只用这五类：`有库存`、`有报价/可订`、`已知无库存`、`无匹配`、`本次未取到`。
- 同一平台多行结果时，表格只保留最能代表平台情况的一行；其他型号或阶梯价放到详细结果。
- 状态归类优先级：有库存 > 有报价/可订 > 已知无库存 > 无匹配 > 本次未取到。
- 不出现采集过程、技术实现、JSON 字段
- `有库存` 行带核心摘要：库存量 + 返回型号 + 最低价/MOQ
- `无匹配` 行可只写平台状态和证据，不解释成“无货”
- component-data 只回 typed 报价行（offers[]）。某源 `ok=true` 但 `offer_count=0` = 正常无匹配，归入 `无匹配`；`ok=false`（error+hint）= 本次未取到、标 `需复核`，都不伪装成 `有库存`。没有 `price_breaks` 就不编价。
- `本次未取到` 写具体原因（反爬拦截/未响应/维护/缺 API key），不写"无货"
- 详细结果中 `返回型号` 后加一致性标注：`✓ 完全一致` / `⚠ 差异：逐字符说明`
- `库存` 写数字 + pcs；`0` 写"已知无库存"，空写"未返回"
- `价格` 取最低阶梯价注明起订量；无阶梯价写"未返回"
- `交期` 有则写原文，无则写"未返回"
- `证据` 优先给产品页链接；没有链接写"来源字段无链接"
- `需确认` 写需要采购人工核实的点；没有写"无"
- 不做采购推荐排序；只呈现平台事实和需确认点。

## Rationalization Table

| Excuse | Reality |
|---|---|
| “我已经查了 DigiKey/Mouser/几个常见平台，可以先总结。” | 这是全量并发跑所有平台，不是常见平台抽样；跑不完就写未完成，不要总结成全平台。 |
| “有结果的平台很多，先把有货渠道详细写完。” | 先给全平台总览表，让采购快速看到哪些平台有货、无匹配或本次未取到；详细结果放在表格后。 |
| “跑了一批平台，就可以说全平台完成。” | 只有 envelope 里每个源都有终态，才能说平台已覆盖完成；缺状态就写未确认。 |
| “平台没返回结果，就是无货。” | 正常无匹配和本次未取到要分开；访问受限不是无货证据。 |
| “型号差一个后缀也算同一个。” | 后缀可能代表包装、温度、速度、版本或封装，必须逐字符说明差异。 |
| “看到价格最低的一行，直接推荐给采购。” | 本 skill 只汇总平台证据；不做供应商准入、下单建议或性价比排序。 |
| “WebSearch 看到库存页，也能报库存价格。” | 库存、价格、可得性只认结构化平台证据；网页搜索只能辅助识别型号信息。 |
| “平台返回 similar/alternate，就能当替代料。” | 平台相似项只是线索，不能在这里下可替代结论。 |
