# 查找替代料

给一个型号：先获取原型号的规格基线，再找候选替代料，逐个把规格跟基线对比、判断是否可以替代，给采购一份可用的替代清单。

## 第零步：先获取原型号的规格基线（对比的标尺）

找替代的本质是“候选规格 vs 原型号规格”，先把原型号关键规格明确，作为后面判断的标尺。怎么拿：

- 用 `procurement-model-info-search`（查清品牌/品类/封装/核心规格/生命周期），或
- 调用 `scrape-engine` 取得少量定向结构化证据（厂牌/品类/封装/datasheet/描述），或
- 从第一步结构化替代候选证据的原型号栏直接读。

记下关键项作标尺：**封装/引脚、核心参数（电压/精度/容值/频率/Memory/接口等）、温度/认证、生命周期**。

⚠️ **跨品牌找等效，匹配键是 datasheet 上的真实参数，不是型号字符串里的数字。** 各家型号的数字段编码规则不同，拿原厂型号里的数字去拼别家型号的数字段，几乎必错。先从 datasheet 把关键工作参数抄出来，用参数找别家同规格料。

## 第一步：找候选

**先分清证据用途，别把找替代干成"全平台搜现货"。** 找替代只需要三类证据：①**规格基线**（model-info 或结构化平台证据，1-2 次够了）②**等效候选**（结构化替代候选源 / cross-reference）③**候选验证**（拿候选反查它的规格）。**不要逐个在现货/比价平台反复搜原型号**——那是查现货的活，对"找替代料"零价值，只会拖时间。发现自己在多个平台搜同一个料的库存，就是跑偏了，停下来回到 ①②③。准确率优先于速度；候选证据弱时继续查原厂页/datasheet/cross-reference/停产替代通知/同基础料号变体，证据足够后收口，不为了库存/价格继续扩平台。

**按"直接程度"找，越直接的越优先，最直接的那种最容易被漏，先找它：**

### 预备步：先判准原型号品类和厂牌

输入若是短名、描述或软件/SKU 名（如只写品类 + 数字、软件套件名、客户内部简称），不要把搜索到的第一个库存结果当成原型号。先用 2-3 个来源确认它到底是哪一类，以及可能厂牌；品类没判准，后面的替代全会跑偏。判准品类后读取对应 reference：

- 硬盘：`references/hard-disk.md`
- 工业存储卡：`references/industrial-memory-cards.md`
- eMMC：`references/emmc.md`
- 内存模组：`references/memory-modules.md`
- DRAM 裸片：`references/dram-ic.md`
- 压敏电阻：`references/varistors.md`
- 电容：`references/capacitors.md`
- 软件 SKU：`references/software-sku.md`
- 继电器：`references/relays.md`
- 连接器：`references/connectors.md`
- 线材：`references/wire-cable.md`
- 工业自动化模块：`references/industrial-automation.md`
- 工业相机：`references/industrial-camera.md`
- RTC / 模块：`references/rtc-modules.md`

### ⓪ 最优先——同一颗芯片换封装/后缀/无铅变体（最直接、最低风险，最易漏！）

先把原型号 MPN 拆成 **基础料号 + 封装/后缀代码**（如 `TPS92550TZ` = 基础 `TPS92550` + 封装后缀 `TZ`；`/NOPB` 是无铅标识）。**同一基础料号、后缀不同 = 同一颗芯片的不同封装/包装/无铅版本**，电气规格完全一致，是最直接的替代，**必须第一个找、找到就置顶**：

- 在结构化替代候选证据和平台证据里留意「同基础料号、后缀不同」的型号（如 `TPS92550TZ/NOPB ←→ TPS92550TZX/NOPB`）；必要时用 `<基础料号>`（去掉封装后缀）反查全部封装变体。
- ⚠️ **常见失误（必须避免）**：明明在对比表里看到了「同芯片换封装」的最直接选项，却绕过去只推姐妹型号或别的芯片（如放着 `TPS92550TZX` 不推、去推 `TPS92551`）。**同料号变体只要出现就必须进清单并排在最前**——它和原型号是同一颗芯片，只需核对封装/引脚对不对得上（封装代码不同未必 pin-to-pin，但永远是首选评估对象，不许跳过）。
- ⚠️ **同基础料号变体不是终点**：找到包装/引线/速度降级/同系列变体后，还要再查一轮 `replacement / successor / alternate / cross reference / migration / superseded by / newer version`。很多业务确认替代不是最像原型号的包装变体，而是官方继任、同厂迁移 SKU、不同系列但明确等效的订货号。

### ① 官方替代、继任型号、订货后缀和版本后缀

主动查这些词，不要只查库存：

- `"<型号>" replacement`, `"<型号>" successor`, `"<型号>" alternate`, `"<型号>" cross reference`, `"<型号>" superseded by`, `"<型号>" equivalent`
- `"<型号>" lifecycle`, `"<型号>" PCN`, `"<型号>" EOL`, `"<型号>" migration`
- 去掉包装/温度/版本后缀后的基础料号，再查 `ordering information`、`part numbering`、`orderable part number`

订货号后缀、版本后缀、温度后缀、包装后缀都要作为候选主动验证：`/ST`、`A/B/C/D revision`、速度/封装修订后缀、认证/包装尾缀、同厂软件套件当前名称等。不要因为某个同系列候选已有库存，就漏掉官方更接近的后继/替代订货号。

**业务确认级替代不要只停在“最像原型号”的候选。** 同基础料号、同系列、包装/渠道、容量或速度变体只能说明你找到了低风险候选；它们不是收口条件。继续查一轮更像采购会确认的关系；具体品类的候选生成顺序和查询词见上面的品类 reference。

### ② 结构化替代候选源（跨品牌 + 规格逐项对比）

调用 `scrape-engine` 获取替代候选证据。

优先读取能直接给出“原型号 vs 替代型号”并排列规格的证据：封装/引脚/内核/主频/Memory/电压/接口/外设，以及可用时附带的价格/库存。**这类证据同时给了候选和第二步判断要的规格对比。**

### ③ 国内替代候选源（带规格摘要）

读取采集层返回的替代候选行：`型号 | 规格摘要 | 品类 | 库存 | 交期 | 阶梯价 | datasheet`。这里只消费字段，不维护接口或爬取方式。

### ④ 网查 cross-reference

WebSearch `"<型号>" cross reference / replacement / equivalent / 替代型号`，找原厂或第三方替换表、停产替代通知（PCN）。

### ⑤ 同品类同规格换品牌（不同芯片，最后考虑）

用上面拿到的真实参数（封装+核心规格），通过结构化平台证据查其它品牌的同规格料作候选。

⚠️ **凭命名规律推断出来的别家型号，必须反查确认才能进清单。** 权威替代源（①②）经常空手，这时按命名规律自己猜一个候选型号是可以的，但**猜完必须拿它去平台/datasheet 反查**：查到、规格对得上，才进清单；查不到资料但看起来仍可能同规格的，最多列为「需补充确认」；查到后发现关键规格明显不同的，直接排除，**不要列进最终替代清单**。型号字符串再相似，没反查过就不是结论。

把候选去重，每个记：替代型号、品牌、规格、来源、库存/价（有就带）。

## 反合理化表格

| 常见借口 | 反驳 |
|---|---|
| “先全平台搜现货，看到有货再说替代。” | 找替代先要规格基线和候选关系；现货只能辅助联系采购，不能决定可替代。 |
| “型号数字很像，应该可以列进最终清单。” | 必须反查 datasheet 或结构化规格；没验证只能写需补充确认，明显冲突直接排除。 |
| “权威替代源没有结果，就随便找几个同系列。” | 先找同基础料号变体，再找同系列和跨品牌同规格；每个候选都要逐项对比。 |
| “已经找到同基础料号/有库存的变体，就不用再找了。” | 同基础料号只是低风险候选；仍要查官方 replacement/successor/cross-reference，业务确认替代经常藏在继任订货号或版本后缀里。 |
| “软件产品找不到同名替代，就列 CrowdStrike/Defender 这类竞品。” | 软件先找同厂产品线迁移、当前命名和 license successor；跨厂竞品不是同厂 SKU 替代。 |
| “短名搜到一个连接器/库存件，就按它继续。” | 短名先判品类；品类错了，规格对比再细也没有意义。 |
| “软件旧 SKU 没有公开一对一替代表，所以还要继续搜。” | 企业软件旧 SKU 往往不公开；同厂当前产品线/迁移层级已经是候选证据，列出并标明缺口，不要无限搜索。 |
| “有货/便宜的候选应该排前面。” | 排序按替代完整度，不按库存或价格。 |
| “候选都找到了，顺手总结最快/最低风险/最佳/性价比方案。” | 不做采购建议和方案排序；只输出候选验证结果，价格/库存只作为字段信息。 |

## 第二步：逐项对比 + 判断每个候选能不能真替

对每个候选，把它的规格跟第零步的**原型号基线逐项对比**（封装/引脚、核心参数、温度、认证、pin 兼容性），再按 `procurement-part-mismatch-review` 的规则收敛结论：

- **结构化替代候选证据**已经把原型号和替代并排列好时，直接读差异最快。
- 其它来源（国内替代候选 / 网查 / 同规格换品牌）的候选：用候选的 datasheet/平台规格 vs 基线对比；规格不全就去查候选的资料补上。
- 收敛：**关键项全兼容 = 可替代；关键项不完整但未发现冲突 = 需补充确认；任一关键项冲突 = 排除，不进最终清单**。别只凭型号相近或规格摘要像就说可替代。
- **替代判断按兼容完整度，不按价格/库存排序。** 价格、库存、交期只是采购后续联系时的辅助信息，不能让一个规格更差、pin 不确认或参数不完整的候选排到更前。
- **明显不一样的候选不要展示。** 例如封装/引脚不兼容、核心电压/容量/阻值/接口/协议/温度等级明显不满足、类别不同、生命周期或认证明显不满足使用要求的型号，过滤掉；不要为了显得结果多，把不可替代的型号列出来。

## 输出

输出是采购/工程可读的验证清单，不是报告。只整理证据和替代判断，不替采购做采购决策。格式如下：

```text
结论：找到 X 个可继续评估的替代候选；明显规格冲突的型号已排除。

原型号基线：<原型号>，<品牌>，<品类>，<封装/引脚>，<核心参数>，<温度/认证/生命周期等关键约束>。

替代候选：
| 候选型号 | 品牌 | 替代关系 | 关键匹配 | 关键差异 | 替代判断 | 证据 | 库存/价格 | 需确认 |
|---|---|---|---|---|---|---|---|---|
| ... | ... | 同料号变体 / 同系列 / 跨品牌同规格 | ... | ... | 可替代 / 需补充确认 | ... | ... | ... |

已排除：
- 不逐条列明显不兼容型号；只概括排除原因，例如“已排除封装/引脚不同、核心参数不满足的候选”。
```

写法要求：
- `原型号基线` 只写一行，不展开成大表。
- `替代候选` 只用一个总表，每个候选一行；多个参数用分号压缩在同一个单元格里。
- 表格行按替代完整度排列：同料号变体、同系列、跨品牌同规格；不另写排序说明。
- `替代判断` 只能写 `可替代` 或 `需补充确认`；明显不可替代的候选已经过滤，不在表内写 `不可替代`。
- `需确认` 写具体工程/采购确认点；没有就写“无”。
- 表后不追加汇总速览、采购建议或结尾追问。

**交清单前自检一遍**：原型号有没有「同基础料号、不同封装/后缀」的变体（去掉封装后缀，用结构化候选源或平台证据反查）？**有就必须在清单里、且排最前**，绝不能找到了却只推别的芯片。没找到可替代的就如实说，并列出查过哪些证据类型、缺什么资料。

## 边界

- **停产/EOL 的同系列后继、原厂官方替代，照样列出并标生命周期，别自己剔掉。** 生命周期是注记不是淘汰理由——原型号往往本身就停产了，采购要的常常正是那个 EOL 的官方后继。已经查到的后继型号不要因为它 EOL 就从清单里删掉。
- 规格摘要相近 ≠ 可替代；结论以差异判断为准。
- 需要采购/工程确认的风险写进 `需确认`，不要另写“最终适用性/最终可用性”说明段。
- 本 skill 负责找候选 + 判断是否可替代。
