## Features

- **Switch Claude accounts in an existing chat** — When you're signed in with more than one Claude subscription, for example a personal and a work plan, the model picker of a started chat now offers Switch account. The conversation, the model and your draft stay, and the next message runs on the account you picked; useful when one account hits its usage limit. Available while the chat is idle, for accounts that offer the chat's model. Fixes [#1155](https://github.com/craft-ai-agents/craft-agents-oss/issues/1155). Thanks to [@seb-veto](https://github.com/seb-veto).

- **Chats change projects together with the chats under them** — Moving a chat to another project now also moves everything nested under it in the session list: the sessions it started, its task's steps and the chats branched from it. Steps a task starts later join the project its chat is in. A chat you moved to another project on its own, or that an agent started in another project, stays where it is. You can also select several chats and choose **Move to Project**, and every move shows how many chats moved, with **Undo**. Working folders and transcripts are not touched. Fixes [#1163](https://github.com/craft-ai-agents/craft-agents-oss/issues/1163). Thanks to [@seb-veto](https://github.com/seb-veto).

- **Use your own Microsoft app for Outlook, Calendar, OneDrive, Teams and SharePoint** — A Microsoft source can now sign in with an app registration of your own instead of the built-in one: add its client ID to the source's config (`microsoftOAuthClientId`), plus its tenant (`microsoftTenantId`) when the app accepts only your organization's accounts. Useful when your organization allows only apps it registered itself, and for builds without a built-in Microsoft app. Switching apps asks you to sign in again. How to register one: [Microsoft App Setup](https://thecraftagents.com/docs/source-guides/microsoft-oauth-setup).

## Improvements

- **Source setup follows your skills first** — When you ask for a new source, the agent now checks your skills before anything else, and follows a skill that covers that service instead of the generic setup steps. Sign-in, Explore mode permissions and the connection test still run. Bundled guides are replaced at every launch, so a skill is the place for setup instructions that should last. Fixes [#1165](https://github.com/craft-ai-agents/craft-agents-oss/issues/1165).

- **Pi SDK 1.6.1** — Updated from 1.1.0, with the changes in between checked against Craft Agents. Pi connections now list GPT-6.2 Astra and GPT-6.2 Sol (OpenAI, ChatGPT, Azure, Amazon Bedrock, GitHub Copilot) and Claude Fable 5.2 (Anthropic, Amazon Bedrock, GitHub Copilot), and models their providers retired are gone. New OpenAI and ChatGPT connections start on GPT-6.2 Astra, which costs less than GPT-6 Astra, and new GitHub Copilot connections on Claude Sonnet 5.5 instead of GPT-5 mini, which Copilot no longer offers. A connection whose default model is no longer listed, such as GPT-5.5 on ChatGPT accounts, gets the new default at the next start, and the model menu of a Pi connection lists the recommended models first instead of alphabetically. Among the upstream fixes: more temporary provider errors are retried automatically, OpenAI no longer rejects and Claude no longer misreads some MCP tool schemas, edits keep the line endings of lines they don't change, and stopping a shell command on macOS no longer runs the next command in its list.

## Bug Fixes

- **A custom endpoint's API key only goes to that endpoint** — On a Pi connection to a custom OpenAI-compatible endpoint, web search called OpenAI's own search API and sent it the endpoint's API key. Web search now uses a provider's own search only when the connection's base URL is that provider's official API (OpenAI, including its EU and US APIs, OpenRouter or Google), and DuckDuckGo otherwise. On custom OpenAI- and Anthropic-compatible endpoints alike, titles, summaries and `call_llm` also stay on the endpoint: a model it doesn't list, or one it rejects, no longer falls back to a built-in OpenAI or Anthropic model, and a session whose model the endpoint doesn't list, or that has none, runs on the endpoint as well.

- **Claude credentials stay with Claude sessions** — The API key or sign-in of the Claude connection that started a session last was also passed to Pi sessions, where the Pi backend could use it and the commands their agent ran could read it. Each connection's credentials now go only to its own sessions.

- **Pi sessions only sign in to their own provider** — When a Pi session's model wasn't available, for example one the Pi catalog has since dropped, the Pi backend picked a default model from any provider it could sign in to, including with an API key it found in the app's environment. A session on an OpenAI or ChatGPT connection could so run on Anthropic. A session now only uses its own connection's provider: a missing model is replaced with that provider's default, or the session doesn't start.

- **OpenAI EU and US connections work on Pi** — Connections set up with the OpenAI EU or US preset had no models, and their chats never reached OpenAI's regional API. They now get OpenAI's models (existing connections at the next start), and every request, web search included, goes to eu.api.openai.com or us.api.openai.com.

- **Personal and work Claude sign-ins aren't flagged as duplicates** — Two Claude subscription connections signed in with the same login but to different organizations, such as a personal plan and a work plan, no longer show the duplicate-account warning in Settings → AI. Connections to the same account and organization still do. Fixes [#1150](https://github.com/craft-ai-agents/craft-agents-oss/issues/1150). Thanks to [@seb-veto](https://github.com/seb-veto).

- **Agents can start sessions from a chat whose project was deleted** — When the chat an agent was working in belonged to a project that had since been deleted, starting another session with `spawn_session` failed with "Project … not found". The new session now starts outside any project.

- **Microsoft sign-in no longer asks for consent every time** — Signing in to a Microsoft source shows the account picker instead of forcing the permissions screen. Work accounts in organizations where only admins may approve apps no longer get "Need admin approval" after their admin has approved the app.

- **Microsoft sources with custom scopes connect** — A Microsoft source that sets only `microsoftScopes` can now sign in. A source whose `microsoftService` doesn't exist, such as `calendar` instead of `microsoft-calendar`, now gets an error listing the valid ones instead of signing in for Outlook mail.
