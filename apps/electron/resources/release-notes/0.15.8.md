## Features

- **Sub-sessions in the session list** — Sessions started from another session now sit under it in the session list: a task's subtasks, sessions an agent starts with `spawn_session`, subtasks added on the Tasks board, and branches. A toggle under the parent's status icon folds its sub-sessions away, and tree lines show which session belongs where. When the parent's second line has nothing else to show, it says how many sub-sessions it has. A family stays together when the list is sorted, grouped (by date, unread, status or project) or loaded page by page, and the list remembers which parents you folded. A branch now also gets its source session's project.

- **Task brief before a task runs** — Opening a task that hasn't run yet shows its goal, acceptance criteria and subtasks, with **Run task** and **Edit task** buttons, instead of the empty new-chat screen.

- **More tools in Coding mode** — Coding sessions now get the built-in browser (while **Built-in browser** is on in Settings), Craft Pages, previews of HTML, PDF, image and Markdown files in the chat, data tables with `transform_data` for large ones, Mermaid diagrams, `call_llm` for focused model calls, `spawn_session`, `get_session_info`, `list_sessions` and the bundled document tools, each with the instructions the regular prompt gives. `source_test` is always available, so the agent can turn on a source itself. A session an agent starts from a Coding session opens in the same folder and in Coding mode. Partially addresses [#1120](https://github.com/craft-ai-agents/craft-agents-oss/issues/1120).

## Improvements

- **Claude Agent SDK 0.3.316** — Claude sessions run on Claude Code 2.1.316 (from 2.1.302). Stop and new messages no longer wait behind a context usage check, and an effort level your organization caps is lowered instead of failing every turn. A session that isn't on the 1M context window and runs past 200K tokens now compacts the conversation and continues, instead of stopping with "Usage credits required for 1M context".

## Bug Fixes

- **A task's agent knows the task** — A session that belongs to a task on the Tasks board started without the task's content, so asking its agent to "do the task" reached an agent that had never seen the goal. The session now gets the task's goal, acceptance criteria and subtasks with your first message, and again whenever the task changes. Other agents can read a task with `get_session_info`, and `list_sessions` marks the sessions of a task. `create_task` now asks for a description that stands on its own, because the agent that runs the task sees none of the conversation that created it.

- **Sources turned on mid-session reach Claude sessions** — A source enabled while a Claude session was running never reached it: the agent kept the tools it started with, and `source_test` only got around this by restarting the session's Claude Code process, which also stopped its background agents. Each new turn now applies the session's current sources, and turning a source off removes its tools. A call a background agent is making to a source finishes before the source changes. When the agent turns on a source in the middle of a turn, the request still restarts with the source's tools, but like Stop it leaves the background agents, workflows and commands it started running.

- **Using a source that isn't enabled no longer stalls the session** — When the agent called a tool of a source that wasn't enabled in the session, Craft enabled the source but ended the turn without a reply, so the session looked stuck until you sent another message. The request now restarts with the source's tools. Fixes [#1102](https://github.com/craft-ai-agents/craft-agents-oss/issues/1102).

- **Replies stopped by Claude's safeguards** — When Claude's safeguards stopped a reply and Claude Code answered it with another model, the stopped reply stayed in the chat, nothing said the model had changed, and the session went on with the other model while the model picker still showed yours. The stopped reply is now removed, a notice says what happened, and the session's model becomes the one that answered: pick yours again to switch back. A reply stopped once and retried gets a notice too. When no other model answers, the chat explains why instead of showing "Invalid Request". Behind a custom endpoint, Claude Code no longer switches to a model the endpoint may not serve.

- **A model picked mid-session is used right away** — In a running Claude session, a model you picked took effect only after the session's Claude Code process restarted. The next message now uses it.

- **Explore mode runs only read-only tools** — Explore mode let any tool it had no rule for run, so tools added in recent Claude Code releases worked there: creating and removing git worktrees, and scheduling prompts. Explore now blocks every tool it doesn't know to be read-only. Subagents still run, but not in their own copy of the repository, and sending messages to other Claude sessions on your computer is blocked. A source tool named like a built-in one, such as Read or WebFetch, is now checked like any other source tool, in Explore and Guarded mode.

- **Pi sessions drop a turned-off source's tools** — In Pi sessions, a source's tools stayed available after you turned the source off, and calling one turned the source back on. They now go with the source.

- **Branches of Pi sessions keep their own conversation** — When the app restarted or the session's tools changed, a branched Pi session's agent got its parent's conversation again in place of the branch's own, and after a restart also what the parent said after the branch point. It now keeps the branch's conversation.

- **Monitor commands follow the permission mode** — Claude's Monitor tool runs a shell command and reports its output as it comes, but Explore mode let any Monitor command run, Ask mode never asked before running one, and Guarded mode didn't check it. Monitor commands now follow the same rules as Bash commands in every mode. A Monitor that only watches a WebSocket is still allowed.

- **HEIC images keep their colors** — On macOS, HEIC photos and screenshots you attach are now converted with the system's own decoder. Colors match the original: iPhone photos (Display P3) are converted to sRGB instead of looking washed out, and no blocks come out in the wrong colors. Conversion is also faster. Windows and Linux keep the previous converter.
