# 方案评估

基于当前方案图片、设计提案和用户约束，生成可追溯的工业设计健康检查，不把单视角推断写成事实。

## 统一交付闭环（强制）

- 先读取当前会话、项目、附件、Source 与上游产物，列出已具备、缺失、冲突及不适用材料；不得要求用户重复提供已有信息。
- 缺少会改变结果的参数或必需素材时，每轮最多询问 1–3 个关键问题并给推荐默认值；必需图片/选区/参考对象缺失时必须阻塞对应生成阶段，不得猜测或伪造。
- 生成前回显目标、输入角色、约束、输出格式、选定 Skill 与逐项验收标准；用户已明确批准相同 Brief 时直接继续。
- 输出必须是本技能交付契约规定的真实文件，并同步维护 `deliverable-brief.md` 与 schema v2 `deliverable-manifest.json`；每次修订递增版本且不覆盖已批准版本。
- 生成后打开或解析全部文件，逐项记录可读性、内容/视觉一致性、保护项、禁止项与失败证据。供应商或工具失败时保持 `draft`，只列真实成功文件。
- 只有真实产物存在、验收项全部有通过证据且用户明确批准后才能标记最终版；否则在右侧成果栏保持草稿、待确认或失败状态。


## 调用与路由

- 用户要求方案评审、设计诊断、成熟度/风险检查、改进建议时适用。
- 与参考对象逐项比较用 `@对标诊断`；提出新方案用 `@设计提案`。

## 界面参数

- `designImages`：至少一张方案图，可来自本地、素材库或项目资产。
- `context`：可选，目标人群、价格带、品牌调性、核心卖点、材料工艺、成本与量产风险。
- 自动继承当前任务的设计提案、造型/CMF 结果和已知工程约束。

## 自动执行

1. 检查证据覆盖的视角和版本，建立观察/推断/未知三层证据。
2. 输出总判断及分层评分：定位与商业、落地风险、造型骨架、CMF 与新意。0–100 分必须注明为专家判断分，不是统计结果。
3. 建立问题优先级，至少包含问题、证据、影响、可能根因、责任角色、修复动作和通过标准。
4. 给出指导建议和后续工作流，路由到造型融合、PI 系列化、CMF 发散、无限画布或必要验证；建议不得超出证据。
5. 按 [references/deliverable-contract.md](references/deliverable-contract.md) 生成预览与状态。后续修订保留稳定问题 ID。

## 渐进式会话

首次有方案图即可评估；缺失参数作为假设。仅当产品对象或评估目标不明时问一个问题。用户补图后更新受影响评分和问题，不重写无关结论。

## 边界

视觉评估不替代 DFM、仿真、法规、专利或用户测试。没有多视角/结构证据时必须降低置信度。
