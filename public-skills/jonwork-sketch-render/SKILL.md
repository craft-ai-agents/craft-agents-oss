# 草图渲染

在保持草图设计意图和关键比例的前提下，实际生成可用于提案展示的产品效果图。

## 统一交付闭环（强制）

- 先读取当前会话、项目、附件、Source 与上游产物，列出已具备、缺失、冲突及不适用材料；不得要求用户重复提供已有信息。
- 缺少会改变结果的参数或必需素材时，每轮最多询问 1–3 个关键问题并给推荐默认值；必需图片/选区/参考对象缺失时必须阻塞对应生成阶段，不得猜测或伪造。
- 生成前回显目标、输入角色、约束、输出格式、选定 Skill 与逐项验收标准；用户已明确批准相同 Brief 时直接继续。
- 输出必须是本技能交付契约规定的真实文件，并同步维护 `deliverable-brief.md` 与 schema v2 `deliverable-manifest.json`；每次修订递增版本且不覆盖已批准版本。
- 生成后打开或解析全部文件，逐项记录可读性、内容/视觉一致性、保护项、禁止项与失败证据。供应商或工具失败时保持 `draft`，只列真实成功文件。
- 只有真实产物存在、验收项全部有通过证据且用户明确批准后才能标记最终版；否则在右侧成果栏保持草稿、待确认或失败状态。


## 调用与路由

- 用户要求草图写实、线稿渲染、概念草图效果图时适用。
- 主体已经是效果图且只改场景用 `@整图编辑`；迁移另一产品造型用 `@造型融合`。

## 界面参数

- `sketchImage`：必填，一张清晰线稿或概念草图。
- `renderReference`：可选，提供材质、光影、比例或造型语言证据。
- `designFeatures`：材质、表面处理、光影、比例、需要保留的细节。
- `aspectRatio`：`1:1`/`3:2`/`2:3`，默认 `1:1`；`count`：1–4，默认 1；`quality`：低/中等/高，默认中等。

## 自动执行

1. 读取草图并列出必须保留的轮廓、结构线、开口、部件关系和视角；不把噪声误当设计特征。
2. 从参考图只提取用户允许的材质、光影或风格，不复制无关造型。
3. 将自然语言整理为工业设计渲染 Brief；必要时标注待验证尺寸或结构，不擅自重构产品。
4. 使用可用图片生成/编辑能力实际生成指定数量的效果图，并核对主体、构图、比例和关键特征一致性。
5. 按 [references/deliverable-contract.md](references/deliverable-contract.md) 保存输入、输出和历史状态并立即展示结果。

## 多轮修订

用户说“材质更细腻、背景改白、轮廓别动”等时直接创建新版本；未受影响参数保持稳定。仅当草图不可辨识或保留项冲突时询问一个问题。

## 边界

不得把生成图描述成已量产照片或工程验证。工具未生成真实图片时，不得创建空占位文件或宣称成功。
