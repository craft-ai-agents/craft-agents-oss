# PI系列化

从同一家族种子产品中提炼稳定 PI 规则，应用到十个产品品类并实际生成系列图。

## 统一交付闭环（强制）

- 先读取当前会话、项目、附件、Source 与上游产物，列出已具备、缺失、冲突及不适用材料；不得要求用户重复提供已有信息。
- 缺少会改变结果的参数或必需素材时，每轮最多询问 1–3 个关键问题并给推荐默认值；必需图片/选区/参考对象缺失时必须阻塞对应生成阶段，不得猜测或伪造。
- 生成前回显目标、输入角色、约束、输出格式、选定 Skill 与逐项验收标准；用户已明确批准相同 Brief 时直接继续。
- 输出必须是本技能交付契约规定的真实文件，并同步维护 `deliverable-brief.md` 与 schema v2 `deliverable-manifest.json`；每次修订递增版本且不覆盖已批准版本。
- 生成后打开或解析全部文件，逐项记录可读性、内容/视觉一致性、保护项、禁止项与失败证据。供应商或工具失败时保持 `draft`，只列真实成功文件。
- 只有真实产物存在、验收项全部有通过证据且用户明确批准后才能标记最终版；否则在右侧成果栏保持草稿、待确认或失败状态。


## 调用与路由

- 用户要求产品家族化、PI 延展、系列产品生成、共享设计语言时适用。
- 只改变单个产品 CMF 用 `@CMF发散`；仅分析 PI 不生成时可先运行 `@智能设计解构`。

## 界面参数

- `seedImages`：必填 2–4 张，同一家族且主体清晰。
- `categories`：可选，每行一个产品品类；系统补足到 10 个。用户明确品类优先且不得替换。
- `piRequirements`：目标用户、场景、价格定位、制造限制和需强化的 PI 细节。
- 输出设置：比例 `1:1`/`3:2`/`2:3`，质量低/中等/高；默认 `1:1`、中等。固定生成 10 款产品。

## 自动执行

1. 识别种子图共同而非偶然的轮廓比例、体块、特征线、界面、部件、CMF 和品牌语义。
2. 形成“必须共享、可按品类适配、禁止机械复制”的 PI 规则；不把单张图片特征误判为家族规则。
3. 补足品类时覆盖不同体量与使用场景，并说明补足逻辑。
4. 为每个品类生成独立 Brief 和图片；检查十款之间的共享识别、品类适配、功能合理性、变化幅度和 CMF 一致性。
5. 按 [references/deliverable-contract.md](references/deliverable-contract.md) 保存 PI 规范、十款结果和历史状态。

## 边界

不得复制种子图中的第三方标识。生成系列是概念设计，不代表工程实现。只有实际生成的图片可计入十款结果；部分失败必须显示缺口。
