# 设计提案

自动整合同一 Craft 任务的最新用户洞察、竞品洞察、附件和对话要求，生成可评审的工业设计提案预览。

## 统一交付闭环（强制）

- 先读取当前会话、项目、附件、Source 与上游产物，列出已具备、缺失、冲突及不适用材料；不得要求用户重复提供已有信息。
- 缺少会改变结果的参数或必需素材时，每轮最多询问 1–3 个关键问题并给推荐默认值；必需图片/选区/参考对象缺失时必须阻塞对应生成阶段，不得猜测或伪造。
- 生成前回显目标、输入角色、约束、输出格式、选定 Skill 与逐项验收标准；用户已明确批准相同 Brief 时直接继续。
- 输出必须是本技能交付契约规定的真实文件，并同步维护 `deliverable-brief.md` 与 schema v2 `deliverable-manifest.json`；每次修订递增版本且不覆盖已批准版本。
- 生成后打开或解析全部文件，逐项记录可读性、内容/视觉一致性、保护项、禁止项与失败证据。供应商或工具失败时保持 `draft`，只列真实成功文件。
- 只有真实产物存在、验收项全部有通过证据且用户明确批准后才能标记最终版；否则在右侧成果栏保持草稿、待确认或失败状态。


## 调用与路由

- 用户要求设计方案、产品概念、工业设计提案、功能定义、造型、CMF、人机或结构方向时适用。
- 显式 `@设计提案` 时优先执行；未引用时按意图自动启用，不要求用户选择技能。
- 用户主要在研究用户或竞品时不要提前收敛方案。若上游产物存在则自动继承；不存在时可生成明确标注假设的概念初稿。

## 最小输入原则

- 产品和设计任务明确后直接生成，不要求用户再次填写已经存在于当前任务或上游结果中的信息。
- 目标用户、市场、场景、需求、竞品机会、品牌倾向和工程约束优先自动继承。缺失内容作为开放假设，不逐项追问。
- 只有产品对象不清楚、互斥约束无法同时满足，或用户必须做取舍时，才一次性提出一个合并问题；其余问题进入 `openQuestions`。
- 最新对话要求优先，例如“安全优先、不要 App、成本控制在 200 元”，直接应用并简短说明变化。

## 界面参数映射

- `proposalTitle`：提案标题/设计任务，是最小必需输入。
- `audience`：评审对象，默认“客户与项目决策者”。
- `reviewStage`：默认“概念方案评审”。
- `focus`：功能创新、造型语言、CMF、结构制造或量产风险。
- `proposalImages`：产品、草图、结构或 CMF 图片；`proposalDocuments`：提案相关文档；`resourceLinks`：每行一个官网、调研、竞品或项目链接。

同一任务已有用户洞察和竞品洞察时自动映射为提案输入，不要求再次上传。状态 JSON 保存界面字段、上游稳定 ID 和来源。

## 自动执行

1. 自动查找并读取 `data/01-用户洞察状态.json`、`data/02-竞品洞察状态.json` 或对应预览；没有上游结果时仍可生成假设型草案，但必须降低置信度。
2. 建立需求与机会到设计原则、概念和验证任务的追溯关系。
3. 自动生成一个推荐主概念；只有存在真实取舍时才生成备选，不为数量制造概念。
4. 完成定位、功能、形态、CMF、人机、结构材料、合规、成本、风险和验证计划。无依据的数值标为 `target_assumption`。
5. 检查重量、尺寸、续航、价格、材料和防护指标的一致性；冲突进入 `decisionItems`，不得静默覆盖。
6. 后续对话读取状态文件，只修改受影响字段并保留稳定 ID。按 [references/deliverable-contract.md](references/deliverable-contract.md) 生成 Craft 可直接预览的提案和内部状态 JSON。

## 渐进式专业会话

1. **快速启动**：产品和设计任务明确后先生成概念初稿；对象不明时只问产品或服务是什么。
2. **产品定位**：预览后逐轮确认目标用户、核心场景、价值主张或需要主动放弃的方向；每轮最多一个问题并提供推荐默认值。
3. **设计定位**：再逐步确认品牌语义、造型风格、CMF、人机重点及是否需要 App/智能化，不用一次问完。
4. **工程定位**：根据方案成熟度确认尺寸、成本、材料、制造、合规和性能约束；缺失时使用目标假设而非阻塞。
5. **决策收敛**：围绕主概念与备选、关键技术取舍、风险和验证门槛询问真正需要用户决定的事项。

只问会显著改变推荐概念或工程可行性的问题。每轮最多一个问题、最多 3 个选项，并提供推荐默认值；可推断内容直接形成假设，已有回答不得重复询问。

用户说“定稿/确认最终版”时，校验追溯关系、12 项 Brief、指标一致性和风险验证后生成 `data/final/03-设计提案最终报告-vN.md` 与对应 `data/final/00-业务闭环最终报告-vN.md`；后续修改创建新版本。

## 状态

默认标记为初稿，不自动提交评审、批准、生成付费图片或 3D。完成后立即渲染报告预览；用户未要求时不额外导出其他格式。

## 实时预览（强制）

- 每次生成或修订后覆盖 `data/03-设计提案预览.md` 和 `data/00-业务闭环预览.md`。
- 立即读取并优先渲染 `03-设计提案预览.md` 的 `markdown-preview`；需要总览时在同一回复中追加闭环预览。
- 所有 `markdown-preview.src` 使用真实绝对路径。禁止输出 `{{SESSION_PATH}}`、相对路径或不可打开的备用链接。
- 预览组件不可用时直接内联报告正文。渲染后简述推荐概念、风险和本轮变化；没有关键冲突时不追问用户。
- 存在一个需要用户取舍的专业问题时，可在预览后提出，并同时给出推荐方案及默认选择；禁止“还想怎么改”式宽泛追问。
