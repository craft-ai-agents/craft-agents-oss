# 整图编辑

锁定主体身份与核心构图，只修改用户指定的全图环境或视觉属性，并实际生成编辑结果。

## 统一交付闭环（强制）

- 先读取当前会话、项目、附件、Source 与上游产物，列出已具备、缺失、冲突及不适用材料；不得要求用户重复提供已有信息。
- 缺少会改变结果的参数或必需素材时，每轮最多询问 1–3 个关键问题并给推荐默认值；必需图片/选区/参考对象缺失时必须阻塞对应生成阶段，不得猜测或伪造。
- 生成前回显目标、输入角色、约束、输出格式、选定 Skill 与逐项验收标准；用户已明确批准相同 Brief 时直接继续。
- 输出必须是本技能交付契约规定的真实文件，并同步维护 `deliverable-brief.md` 与 schema v2 `deliverable-manifest.json`；每次修订递增版本且不覆盖已批准版本。
- 生成后打开或解析全部文件，逐项记录可读性、内容/视觉一致性、保护项、禁止项与失败证据。供应商或工具失败时保持 `draft`，只列真实成功文件。
- 只有真实产物存在、验收项全部有通过证据且用户明确批准后才能标记最终版；否则在右侧成果栏保持草稿、待确认或失败状态。


## 调用与路由

- 用户说“产品不变，换背景/光线/天气/材质/风格”时适用。
- 改局部零件用 `@局部改型`；把参考产品的造型语言融入主体用 `@造型融合`。

## 界面参数

- `sourceImage`：必填，要保留主体和构图的原图。
- `sceneReference`：可选，参考环境、光线、天气或氛围。
- `editRequirements`：要修改的场景、背景、时段、天气、光线、颜色、材质或风格，以及禁止变化项。
- `aspectRatio`：`1:1`/`3:2`/`2:3`；`count`：1–4；`quality`：低/中等/高。默认 `1:1`、1、中等。

## 自动执行

1. 先识别并锁定产品轮廓、视角、尺度、品牌特征、部件和构图关系。
2. 将要求分成可变项与锁定项；参考图只提供环境/氛围证据，不迁移其产品造型。
3. 实际调用图片编辑能力生成结果；检查主体漂移、部件增删、文字标识变形和构图变化。
4. 若检查不通过，在授权的生成次数内重试；仍不通过则标记失败，不把不合格图列为成功输出。
5. 按 [references/deliverable-contract.md](references/deliverable-contract.md) 保存并预览。

## 多轮修订与边界

最新要求覆盖对应可变项，其余锁定项保持不变。用户未要求时不进行局部结构重设计，不把编辑图当作真实场景证据。
