# 用户洞察

把用户当前消息、同一 Craft 任务中的历史要求、附件、Sources 和已有产物合并为一个 Brief，直接生成可预览的用户洞察。

## 统一交付闭环（强制）

- 先读取当前会话、项目、附件、Source 与上游产物，列出已具备、缺失、冲突及不适用材料；不得要求用户重复提供已有信息。
- 缺少会改变结果的参数或必需素材时，每轮最多询问 1–3 个关键问题并给推荐默认值；必需图片/选区/参考对象缺失时必须阻塞对应生成阶段，不得猜测或伪造。
- 生成前回显目标、输入角色、约束、输出格式、选定 Skill 与逐项验收标准；用户已明确批准相同 Brief 时直接继续。
- 输出必须是本技能交付契约规定的真实文件，并同步维护 `deliverable-brief.md` 与 schema v2 `deliverable-manifest.json`；每次修订递增版本且不覆盖已批准版本。
- 生成后打开或解析全部文件，逐项记录可读性、内容/视觉一致性、保护项、禁止项与失败证据。供应商或工具失败时保持 `draft`，只列真实成功文件。
- 只有真实产物存在、验收项全部有通过证据且用户明确批准后才能标记最终版；否则在右侧成果栏保持草稿、待确认或失败状态。


## 调用与路由

- 用户提到用户研究、用户画像、使用场景、体验地图、痛点、需求、机会或“先了解用户”时适用。
- 用户显式 `@用户洞察` 时优先按本技能执行。未显式引用时，根据上述意图自动启用，不要求用户选择技能。
- 请求明显属于竞品对标或设计方案时不要抢占；跨阶段请求优先从缺失的最早上游阶段开始，并说明当前正在做用户洞察。

## 最小输入原则

- 用户通常只需说清产品或研究任务，例如“研究家用电热水壶，重点安全和清洁”。收到后立即工作，不逐项索要市场、用户、场景、关注点、价格等可推断信息。
- 只有产品对象无法判断或最新要求互相冲突时，才一次性提出一个合并问题；其他缺口使用合理默认值，并在结果中标为 `assumption`。
- 多轮对话用于补充或修改，最新明确要求优先；不要让用户重述本任务中已经出现的信息。
- 只使用当前 Craft 任务、当前项目和用户明确提到的 Source；不读取其他项目或验收示例。

## 界面参数映射

- `researchTask`：研究任务，唯一必需的自然语言核心输入。
- `targetMarket`：目标市场，界面默认“中国大陆”。
- `targetUser`：目标用户，界面默认“居家日常用户”。
- `coreScenario`：核心场景，界面默认“日常高频使用”。
- `focus`：可选，人体工学、情绪体验、制造、维护或成本等重点。
- `researchImages`：0–5 张产品、场景、结构、CMF 或现有方案图片。
- `researchDocuments`：0–5 个 PDF、Word、PPT、表格、Markdown 或文本资料。
- `resourceLinks`：可选，每行一个调研、评论、行业报告或项目链接。

自然语言与当前任务材料自动映射到这些字段；只有 `researchTask` 无法判断时才阻塞。状态 JSON 保留这些字段及其 `user/evidence/assumption` 来源。

## 自动执行

1. 规范化当前任务上下文；保留用户原话，自动补齐项标明为系统假设。
2. 自动读取当前任务附件、项目资产和相关 Source。按材料情况选择：有一手证据为 `evidence`，只有任务描述为 `hypothesis`，两者并存为 `mixed`。
3. 没有一手证据也要生成完整预览，不阻塞、不伪称真实调研；公开资料只能作二手佐证。
4. 建立画像、场景、体验阶段、痛点、需求、机会和概念之间的引用关系。事实、推断、假设分层。
5. 首次调用生成完整预览；后续对话基于状态文件修订，未受影响章节保持稳定，并向用户简短说明本轮变化。
6. 按 [references/deliverable-contract.md](references/deliverable-contract.md) 生成 Craft 可直接预览的 Markdown 和内部状态 JSON。完成后立即渲染报告预览。

## 渐进式专业会话

按信息价值逐步深入，不把问题一次性堆给用户：

1. **快速启动**：只要产品/服务对象明确，就先生成假设型初稿；对象不明确时只问“你想研究什么产品或服务？”
2. **用户定位**：初稿后仅在会显著改变结果时询问一个问题，优先确认核心人群或关键场景，并给出最多 3 个选项及推荐默认值。
3. **问题深化**：再根据缺口逐轮确认行为、障碍、动机、地区或使用约束；每轮最多一个问题，用户不回答则沿用默认假设。
4. **证据深化**：有必要时提示用户可上传访谈、评论或研究资料，但不得把上传设为继续工作的前提。
5. **决策收敛**：围绕最高价值的痛点、需求优先级和概念方向询问取舍，不重复已经回答的问题。

把问题分为三类：阻止正确理解的“必问”、显著改变结果的“可选高价值”、可合理推断的“无需问”。只有前两类能出现；高价值问题放在预览之后并注明“不回答将采用哪个默认值”。

用户说“定稿/确认最终版”时，先校验事实与假设、引用和章节完整性，再生成 `data/final/01-用户洞察最终报告-vN.md`。之后的修改创建新版本，不覆盖既有定稿。

## 交互与状态

- 默认标记为“初稿/待验证”，不得把假设写成已验证结论。
- 用户说“老人优先”“不要 App”等简短要求时，直接应用并重生成，不要求填写结构化参数。
- 不修改数据库或审批状态。用户未要求其他格式时，不额外生成 PDF、PPT 或图片。

## 实时预览（强制）

- 每次首次生成或修订后，都必须覆盖 `data/01-用户洞察预览.md`，随后立即读取该文件并在当前回复中渲染 `markdown-preview`。
- `markdown-preview.src` 必须使用本次会话文件的真实绝对路径。禁止输出 `{{SESSION_PATH}}`、相对路径、反斜杠占位链接或让用户自行寻找文件。
- 如果当前运行环境不能渲染 `markdown-preview`，直接在回复中展示完整 Markdown 内容，不退化成不可打开的文件链接。
- 预览渲染成功后只简述证据状态和本轮变化；没有关键歧义时不以开放问题结尾。
- 存在一个高价值专业缺口时，可在预览后提出一个具体问题，并同时给出推荐默认答案；不要使用“还想改什么”这类宽泛追问。
