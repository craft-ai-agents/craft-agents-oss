# 自定义模式

把当前任务、上游设计提案和最多五张输入图片合并为可执行的融合 Brief，并实际生成图片结果。

## 统一交付闭环（强制）

- 先读取当前会话、项目、附件、Source 与上游产物，列出已具备、缺失、冲突及不适用材料；不得要求用户重复提供已有信息。
- 缺少会改变结果的参数或必需素材时，每轮最多询问 1–3 个关键问题并给推荐默认值；必需图片/选区/参考对象缺失时必须阻塞对应生成阶段，不得猜测或伪造。
- 生成前回显目标、输入角色、约束、输出格式、选定 Skill 与逐项验收标准；用户已明确批准相同 Brief 时直接继续。
- 输出必须是本技能交付契约规定的真实文件，并同步维护 `deliverable-brief.md` 与 schema v2 `deliverable-manifest.json`；每次修订递增版本且不覆盖已批准版本。
- 生成后打开或解析全部文件，逐项记录可读性、内容/视觉一致性、保护项、禁止项与失败证据。供应商或工具失败时保持 `draft`，只列真实成功文件。
- 只有真实产物存在、验收项全部有通过证据且用户明确批准后才能标记最终版；否则在右侧成果栏保持草稿、待确认或失败状态。


## 调用与路由

- 用户要求“以图1为主体、采用图2把手、图3材质”等多图定向融合时适用。
- 只做草图写实化用 `@草图渲染`；保持主体仅改环境用 `@整图编辑`；单一参考造型迁移用 `@造型融合`。
- 未显式调用时，只有用户明确指定多张图的部件/材质来源关系才自动启用。

## 界面参数

- `sourceImages`：1–5 张，上传顺序固定映射为图1…图5。
- `designRequirements`：必填，明确主体、要迁移的部位、材质和禁止变化项。
- `aspectRatio`：`1:1`、`3:2`、`2:3`，默认 `1:1`。
- `count`：1–4，默认 1；`quality`：低/中等/高，默认中等。
- 用户一句自然语言即可启动；缺省项用上述默认值，不逐字段追问。图片角色冲突或主体不明确时只问一个问题。

## 自动执行

1. 按上传顺序建立图号与文件名映射，先回显映射，避免误用参考图。
2. 从设计提案继承产品定位、造型语言、CMF 与不可变约束；用户本轮要求优先。
3. 将要求改写为“主体锁定、部件迁移、材质迁移、整体协调、禁止变化”五类生成约束。
4. 使用可用的图片生成/编辑能力实际生成指定数量的图片；不得只输出提示词或伪造文件。
5. 按 [references/deliverable-contract.md](references/deliverable-contract.md) 保存结果与状态并展示图片预览。后续修改仅变更受影响约束，保留稳定图片与版本 ID。

## 边界

未经用户要求不把图片上传到外部服务、不批准方案、不产生付费批量任务。生成能力不可用时明确报告缺失能力，不用文本结果冒充图片。
